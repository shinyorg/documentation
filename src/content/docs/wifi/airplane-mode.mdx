---
title: Airplane Mode
description: Read and where possible set airplane mode with Shiny.Net.Wifi, and send the user to the right settings screen everywhere else
---

`IAirplaneMode` reads airplane mode, and sets it on the two platforms that allow it.

## No phone lets you toggle it

This is worth stating plainly, because it is the single most common request this API gets and the
answer is the same on both mobile platforms:

- **Android** made `Settings.Global.AIRPLANE_MODE_ON` write-protected in Android 4.2. Writing it
  needs `WRITE_SECURE_SETTINGS`, a signature-level permission that cannot be granted to an installed
  app. Reading it is fine.
- **iOS** exposes neither the state nor a switch. The `App-Prefs:` URL scheme that deep-links to the
  airplane mode row is private API and gets apps rejected.

## Two different flags

```csharp
if (airplane.IsSupported)
    Console.WriteLine($"Airplane mode: {airplane.IsEnabled}");

if (airplane.CanToggle)
    await airplane.SetEnabled(true, ct);
else
    await airplane.OpenSettings(ct);
```

`IsSupported` means the state can be **read**. `CanToggle` means it can be **set**. They are separate
because Android can do the first and not the second.

:::caution[`IsEnabled` is false where it is not supported]
That is not the same as "airplane mode is off". Check `IsSupported` before you show the value —
otherwise an iOS user in airplane mode sees a UI claiming they are not.
:::

| Platform | Read | Set | Backed by |
|----------|------|-----|-----------|
| Android | ✅ | ❌ | `Settings.Global.AIRPLANE_MODE_ON` + the `ACTION_AIRPLANE_MODE_CHANGED` broadcast |
| iOS / Mac Catalyst | ❌ | ❌ | nothing — Apple exposes no API |
| macOS | ❌ | ❌ | macOS has no airplane mode |
| Windows | ⚠️ inferred | ⚠️ all radios | `Windows.Devices.Radios` |
| Linux | ✅ | ✅ | NetworkManager `WirelessEnabled` + `WwanEnabled` |

## Windows is an approximation

WinRT has no airplane mode API. What the Settings toggle actually does is switch every radio off at
once, so that is what `SetEnabled` does, and `IsEnabled` reports true when no radio is left on.

The approximation shows in one place: turning Wi-Fi and Bluetooth off individually makes `IsEnabled`
read true even though the Settings toggle shows off. Needs the `radios` capability in the app
manifest.

## macOS has no such concept

Use [`IWifiManager.SetRadioEnabled`](/wifi/networks/#powering-the-radio) instead — that is what a Mac
user means by "turn the wireless off", and CoreWLAN supports it properly. `OpenSettings()` opens the
Network pane of System Settings.

## Linux maps to the kill switches

What desktop environments label "Airplane Mode" *is* NetworkManager's `WirelessEnabled` and
`WwanEnabled` soft-blocks, which it drives through rfkill. Both off reads as airplane mode on.

Setting either goes through polkit (`org.freedesktop.NetworkManager.enable-disable-wifi` and
`…enable-disable-wwan`) — interactive on a desktop, and needing a rule in a headless session. A
*hardware* kill switch overrides all of it and cannot be cleared from software.

## `OpenSettings` is the universal fallback

```csharp
await airplane.OpenSettings(ct);
```

It goes as close to the switch as the platform allows:

| Platform | Lands on |
|----------|----------|
| Android | The airplane mode settings screen (`ACTION_AIRPLANE_MODE_SETTINGS`) |
| iOS / Mac Catalyst | Your app's own settings page — the closest a sandboxed app can get |
| macOS | The Network pane of System Settings |
| Windows | `ms-settings:network-airplanemode` |
| Linux | Handed to `xdg-open`; GNOME and KDE both register a handler, a bare window manager does not |

The one place it does not work is plain server .NET, which has no settings UI to open and throws.

## Watching for changes

```csharp
airplane.Changed += (_, enabled) => this.isFlying = enabled;
```

Raised on Android (off the system broadcast), Windows (off `Radio.StateChanged`) and Linux (off
NetworkManager's `PropertiesChanged`, filtered so unrelated property churn does not leak through).
Never raised on Apple's platforms, where there is no state to watch.
