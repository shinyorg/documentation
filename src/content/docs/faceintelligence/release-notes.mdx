## 1.0 TBD
<RN type="feature">**`FrameObserved` reports every analyzed frame.** `FaceRecognitionAnalyzer` and `FaceRecognitionView` raise a `FaceFrameObservation` per frame, with a session/frame stamp, face count, bounds, confidence, quality (brightness and sharpness) and any conversion error. Recognition now runs in the background so a slow embed doesn't stall detection, `FaceRecognizedEventArgs.Stamp` names the frame a result came from, and results from a stopped session are never raised. Several faces still track the most confident one, and quality is measured only while observed and never blocks recognition. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) ([#9](https://github.com/shinyorg/recogintelligence/pull/9))</RN>
<RN type="feature">**`FaceEnrollmentView` run lifecycle.** The identity and steps are fixed when a run starts. `CancelEnrollmentAsync()` and `StopAsync()` wait for a store already under way and return every stored `FaceEnrollmentCapture`, and `HasUncertainStorage` flags a store that threw. `ResumePreview()` restarts the camera, and a quick stop-then-start can no longer leave a black preview. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) ([#5](https://github.com/shinyorg/recogintelligence/pull/5))</RN>
<RN type="feature">**Your own UI on top of `FaceEnrollmentView`.** `ShowGuide` and `ShowInstructionBanner` (or `ShowBuiltInOverlay` for both) can be switched off separately. New `CountdownChanged`, `GuideFeedbackChanged` and `CaptureAccepted` events, plus `AcceptedHoldDuration`, `CaptureEnabled` to pause capture, a zero `StepCountdown`, guide colours and an animated colour transition. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) ([#6](https://github.com/shinyorg/recogintelligence/pull/6), [#10](https://github.com/shinyorg/recogintelligence/pull/10))</RN>
<RN type="enhancement">**`FaceRecognitionView` gets an optional guide and lifecycle control:** `Guide`/`ShowGuide` with `GuideFeedbackChanged` and `IsInsideGuide`, a bindable `IsActive` to pause the camera on the page, `DrainAsync`, and `AnalyzerReady`. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) ([#9](https://github.com/shinyorg/recogintelligence/pull/9), [#10](https://github.com/shinyorg/recogintelligence/pull/10))</RN>
<RN type="fix">**Android front camera: frames are no longer upside down.** `FrameImageConverter` mirrored the frame before rotating it, but `CameraFrame` is defined as rotate first, then mirror. On a rotated, mirrored frame (Android front camera, rotation 270) the image came out upside down, so detection and recognition were working on a flipped face. iOS was never affected, because Apple frames always arrive with rotation 0. All eight rotation × mirror combinations are now covered by pixel-level tests. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) ([#3](https://github.com/shinyorg/recogintelligence/pull/3))</RN>
<RN type="fix">**Android: `MaxAnalysisWidth` now caps the upright frame.** The YUV conversion subsampled by an integer step worked out from the sensor width, so a frame could come out up to almost twice `MaxAnalysisWidth` wide, and wider again after rotation. The width limit now runs after orientation, as on iOS. A failed resize keeps the original bitmap instead of returning a disposed one. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) ([#2](https://github.com/shinyorg/recogintelligence/pull/2))</RN>
<RN type="fix">**`FaceRecognitionView` and `FaceEnrollmentView` analyze frames again after navigating back.** Stopping a control detached its analyzer from the camera, but restarting it did not re-attach it, so on a second visit to the page the preview ran with nothing detecting, recognizing or enrolling. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) for the diagnosis ([#5](https://github.com/shinyorg/recogintelligence/pull/5))</RN>
<RN type="feature">**`IFaceIntelligence.ForgetShots(personIdentifier, shotIds)` removes selected shots.** It deletes only the given `Person.Id` documents, and only where they belong to that identity, in one statement, so a single enrollment run can be redone without forgetting the person. Custom stores implement `IFaceStore.RemoveShots`. It has a default implementation that throws `NotSupportedException`, so existing stores still compile. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) ([#7](https://github.com/shinyorg/recogintelligence/pull/7))</RN>
<RN type="feature">**`FaceEnrollmentResult.Captures` lists every stored shot of a guided run:** the step it came from (indices are never renumbered, so skipped steps show as gaps), the stored `ShotId` to pass to `ForgetShots`, and the analysis JPEG that was actually embedded, with its size. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) ([#4](https://github.com/shinyorg/recogintelligence/pull/4))</RN>
<RN type="enhancement">**`FaceGuide.OvalAspectRatio` sets the shape of the enrollment oval.** The default is 0.78. The ratio is measured in view pixels, so the oval keeps its shape on any frame aspect. It changes only the drawing, not the alignment gate. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) ([#8](https://github.com/shinyorg/recogintelligence/pull/8))</RN>
<RN type="enhancement">**Windows (build from source):** on a Windows host, `Shiny.FaceIntelligence.Maui` also targets `net10.0-windows10.0.19041.0`, with a `WindowsCameraFrame` converter that uses the same orientation and width pipeline. The published package is built on macOS and does not include the Windows target yet. The Sample also gets `fetch-models.ps1`, a PowerShell model downloader. Thanks to Jos Menhart ([@Josbourne2](https://github.com/Josbourne2)) of [SoberCheck](https://www.sobercheck.nl) ([#1](https://github.com/shinyorg/recogintelligence/pull/1)), ([#11](https://github.com/shinyorg/recogintelligence/pull/11))</RN>
<RN type="feature">Initial release — on-device face enrollment and recognition split across a dependency-free core plus swappable embedder, detector and store packages, composed with `AddFaceIntelligence`.</RN>
<RN type="feature">`IFaceIntelligence` — `Enroll` / `Recognize` (with or without a face box), `GetAll`, and `Forget`, keyed on a caller-chosen `PersonIdentifier`.</RN>
<RN type="feature">`Shiny.FaceIntelligence.Onnx` — ArcFace embedder (`UseOnnxEmbedder`) and UltraFace detector (`UseOnnxDetector`), both loading their model lazily on first use so a missing model never breaks startup.</RN>
<RN type="feature">`Shiny.FaceIntelligence.DocumentDb` / `.DocumentDb.Sqlite` — vector storage and nearest-neighbour search over Shiny.DocumentDb, with the vector dimension read from the embedder so it always matches the model. sqlite-vec is registered as a SQLite auto-extension so it works on iOS.</RN>
<RN type="feature">`Shiny.FaceIntelligence.Maui` — `FaceRecognitionView` for continuous live identification and `FaceEnrollmentView`, a guided multi-shot wizard with a face-hole overlay, quality gates and an embedding-novelty check.</RN>
<RN type="feature">Detection gating on the no-box `Enroll` — `FaceDetectionException` for no face, low confidence, multiple faces or a face too small, and `FaceEnrollmentConflictException` when the face already matches a different enrolled identity.</RN>
<RN type="feature">AOT- and trim-compatible across every package, with a source-generated `JsonSerializerContext` for the stored document type.</RN>
<RN type="feature">Automatic iOS / Mac Catalyst linker fix for ONNX Runtime's `_RegisterCustomOps` symbol, shipped as `buildTransitive` MSBuild targets so consuming app heads need no configuration.</RN>
