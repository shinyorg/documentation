---
title: Questions
description: The built-in ask_user tool gives a session typed questions with optional multiple-choice answers, so the app knows the AI is waiting on the user
---

A conversation needs to know one thing that a plain chat transcript doesn't show: **is the AI waiting on the user?** If it is, a voice app keeps the microphone open for the answer and a chat app can show answer buttons. If it isn't, the conversation goes back to idle.

`IChatClient` has no signal for that. `ChatFinishReason` is only `Stop` / `Length` / `ToolCalls` / `ContentFilter`. So every session gives the model a built-in tool, **`ask_user`**, and reads the signal from whether the model called it.

## How it works

- The model streams a **plain-text reply**, and phrases the question in that reply as it normally would.
- When it needs an answer, it also calls `ask_user` with the questions, each with an optional fixed set of choices.
- The tool is **terminating**: the turn ends right after the call, without another round trip to the model.
- The turn completes with `AiTurnOutcome.AwaitingUser`, the session's state is `AwaitingUser`, and `session.PendingQuestions` holds the questions. A `QuestionsAsked` turn event carries them too.

The reply text is what the user reads and hears. The questions only drive the interface: answer chips and a reopened microphone.

The schema the model sees:

```text
ask_user(questions: [{ id, text, choices?: [{ id, label }], allowMultiple? }])
```

## The types

```csharp
public record AiQuestion(string Id, string Text, IReadOnlyList<AiChoice>? Choices = null, bool AllowMultiple = false)
{
    public bool HasChoices { get; }
}

public record AiChoice(string Id, string Label);
```

Missing question ids become `q1`, `q2`, …; questions with no text and choices with no label are dropped.

## Answering

```csharp
var result = await session.Send(AiInput.Text("Book me a table for Friday")).Completion;

if (result.Outcome == AiTurnOutcome.AwaitingUser)
{
    foreach (var q in session.PendingQuestions)
        Console.WriteLine($"{q.Text} {(q.HasChoices ? String.Join(" / ", q.Choices!.Select(c => c.Label)) : "")}");
}

// tapping a choice
var question = session.PendingQuestions[0];
await session.Send(AiInput.Answer(question, "7pm")).Completion;

// or a free-form answer, typed or spoken
await session.Send(AiInput.Text("Make it 8 instead")).Completion;
```

`AiInput.Answer(question, params string[] choiceIds)` stores an `AnswerPart` and sends the choice **labels** to the model as the user's message ("7:00 PM"). The model already has the question and its choices in context from the tool call, so nothing is matched locally.

## Each turn replaces the pending questions

Pending questions are cleared when a turn starts and set again from that turn's `ask_user` call. The model is the source of truth for what it still needs: anything it stopped asking about counts as answered, and anything still outstanding it asks again. Pending questions are persisted in the session header, so a session loaded later is still `AwaitingUser`.

## Voice asks one question at a time

When the input came from speech (`AiInput.Voice(...)`), the tool's description tells the model to ask **at most one question**, and only the first question is kept if it sends more. Three questions in one breath read fine as chips and are unusable as audio. Typed input can get several independent questions at once.

## Fallback: a reply that ends with `?`

Some models never call tools. If a turn finishes without an `ask_user` call but the reply ends with a question mark, the session still treats it as waiting on the user: the outcome is `AwaitingUser` and `PendingQuestions` holds a single free-form question (id `reply`) with the last sentence of the reply as its text. Nothing hard-fails either way: unexpected output from the model is kept as plain text.

## What's stored

The `ask_user` call and its result are stored as `ToolCallPart` / `ToolResultPart` on the assistant message (both `ModelOnly`) and replayed to the model as a normal tool exchange on the next turn. The message's display `Text` contains only the reply; there's no JSON envelope anywhere in the transcript.

:::note[Coming from 2.x]
The 3.0 previews asked the model for a JSON `AiTurn` envelope (`AiTurnSerializer`, `IChatClientProvider.StructuredOutputMode`). That approach made streaming impossible and is gone; `ask_user` replaces it.
:::
