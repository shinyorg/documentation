---
title: Wake Word
description: Hands-free activation for voice conversations, what it costs with cloud speech-to-text, and on-device wake word detection
---

A wake word gives a hands-free "Hey Siri" experience: the [voice conversation](/aiconversation/voice) listens for a phrase, then captures what the user says next and sends it to the session.

```csharp
await voice.Attach(session, new VoiceOptions { WakeWord = "hey shiny" });
```

With a wake word set, the loop opens the microphone as soon as the session is attached and waits in `WaitingForWakeWord`. When the phrase is heard it moves to `Listening`, sends the next utterance, speaks the reply, and goes back to waiting. If the AI asked something, it listens for the answer without the wake word first (`FollowUp`, see [Voice](/aiconversation/voice#the-voice-loop)). Push-to-talk keeps working while a wake word is set.

A wake word heard before the loop started waiting is dropped as stale, so an old detection never starts a new turn.

## Off by default

`WakeWord` is `null` by default, which means push-to-talk only and a closed microphone. Only the app can choose the phrase, and an always-listening microphone has battery, privacy and (with cloud speech-to-text) cost implications.

## The cost with cloud speech-to-text

Without help, the wake word is matched by the speech-to-text engine itself: it is passed as a keyword, and cloud providers detect keywords by **transcribing everything** and matching the results. An always-on wake word therefore streams all room audio to the cloud, with per-minute cost, battery drain and privacy implications.

Your options, best first:

1. **An on-device wake word detector** (below). Fixes cost and privacy: the cloud recognizer is only opened after the wake word.
2. **Push-to-talk** on platforms where you use cloud speech-to-text (for example Android, where the built-in recognizer isn't good enough for conversation).
3. **Accept the cost**: it works, it's just billed and always listening.

## On-device detection: `IWakeWordDetector`

Register an `IWakeWordDetector` and the voice conversation uses it instead of the recognizer while waiting for the wake word. Speech-to-text stays **closed** in `WaitingForWakeWord` and only opens once the detector hears the phrase:

```csharp
public interface IWakeWordDetector
{
    // yield each time one of the wake words is heard, until cancelled
    IAsyncEnumerable<string> Listen(IReadOnlyList<string> wakeWords, CancellationToken ct);
}

builder.Services.AddSingleton<IWakeWordDetector, MyKeywordSpotter>();
```

Wrap any on-device keyword spotter (an openWakeWord or Porcupine model, a platform API) in this interface. Shiny doesn't ship a detector model. When a detector is registered the wake word is no longer passed to the recognizer as a keyword.
