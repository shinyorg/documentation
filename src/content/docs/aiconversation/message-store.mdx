`IAiSessionStore` persists sessions. It is the only source of truth: the session manager keeps nothing in memory, so every `Get` reads the store.

The default is `InMemoryAiSessionStore`, which is fine for tests and for apps that don't need history to survive a restart. For persistence, use the SQLite store package below or implement the interface yourself.

```csharp
builder.Services.AddShinyAiConversation(opts =>
{
    opts.SetSessionStore<MySessionStore>();
});
```

## SQLite store

<NugetBadge name="Shiny.AiConversation.Stores.SqliteDocDb" showLabel={true} />

```bash
dotnet add package Shiny.AiConversation.Stores.SqliteDocDb
```

`Shiny.AiConversation.Stores.SqliteDocDb` stores sessions, messages and [assistant memory](/aiconversation/memory) in one SQLite database through [Shiny.DocumentDb](/documentdb/). It replaces the 2.x `Shiny.AiConversation.MessageStores.SqliteDocDb` package.

```csharp
builder.Services.AddShinyAiConversation(opts =>
{
    // registers IAiSessionStore and IAiMemoryStore
    opts.SetSqliteDocDbStores(Path.Combine(FileSystem.AppDataDirectory, "ai.db"));
});
```

Already using a named Shiny.DocumentDb store? Point both stores at it with `SetDocDbStores(key)`. Its options must call `MapAiConversation()`, which adds the JSON metadata, the version mappings and the full-text index the stores rely on:

```csharp
builder.Services.AddDocumentStore("app", opts =>
{
    opts.DatabaseProvider = new SqliteDatabaseProvider("Data Source=app.db");
    opts.MapAiConversation();
});

builder.Services.AddShinyAiConversation(opts => opts.SetDocDbStores("app"));
```

What it does to stay safe with several writers:

| Concern | How |
|---|---|
| Header saves | the header is stored in a version-mapped document, so the database rejects a save from a stale version and the store throws `SessionConflictException` |
| Message sequence | a version-mapped counter per session is incremented in the **same transaction** as the message insert; a conflicting writer rolls back and retries with the next number |
| Memory documents | version-checked the same way (`MemoryConflictException`) |
| Search | `SearchMessages` uses the database's full-text index (FTS5 on SQLite): ranked, with stemming, over user and assistant text only |
| Queries | indexes on message session id and sequence, and on session last activity |

The core documents are nested inside small storage wrappers (`StoredAiSession`, `StoredAiMessage`, `StoredAiSequence`, `StoredAiMemory`) that carry the id, the version and a few denormalized query fields.

:::note[Encryption at rest]
The store doesn't encrypt conversations. If you need that, use an encrypted database provider (for example SQLCipher with Shiny.DocumentDb) or your own `IAiSessionStore`.
:::

## Two document types

| Document | Shape | Written |
|---|---|---|
| `AiSessionDocument` (header) | small, updated in place: title, settings, rolling summary, pending questions, usage, context size, message count | after every turn, and on `SetTitle` / `UpdateSettings` |
| `AiMessageDocument` | append-only, one per message, ordered by `Sequence` | user message before the model is called; assistant message as `Streaming`, then finalized |

A turn never rewrites a growing document: messages are appended, and the assistant message is updated once when the turn ends.

```csharp
public record AiMessageDocument(
    string MessageId,
    string SessionId,
    long Sequence,                 // allocated by the store
    int SchemaVersion,
    DateTimeOffset Timestamp,
    MessageRole Role,              // User | Assistant | Tool | System | Summary
    MessageSource Source,          // Typed | Voice | ChoiceAnswer | Model | ...
    MessageStatus Status,          // Complete | Streaming | Interrupted | Failed
    IReadOnlyList<MessagePart> Parts,
    string? Text,                  // display text, for search and UI
    string? SpokenText,            // what was heard, when interrupted
    UsageSnapshot? Usage,
    bool Compacted,
    string? CompactedIntoMessageId,
    string RunId                   // the process run that wrote it (crash recovery)
);
```

`MessagePart` is polymorphic (`TextPart`, `ToolCallPart`, `ToolResultPart`, `AnswerPart`), with a `kind` discriminator in JSON.

## Interface

```csharp
public interface IAiSessionStore
{
    Task CreateSession(AiSessionDocument session, CancellationToken ct = default);
    Task SaveSession(AiSessionDocument session, long expectedVersion, CancellationToken ct = default);
    Task<AiSessionDocument?> GetSession(string sessionId, CancellationToken ct = default);
    Task<IReadOnlyList<AiSessionDocument>> QuerySessions(SessionQuery query, CancellationToken ct = default);
    Task DeleteSession(string sessionId, CancellationToken ct = default);

    Task<AiMessageDocument> AppendMessage(AiMessageDocument message, CancellationToken ct = default);
    Task UpdateMessage(AiMessageDocument message, CancellationToken ct = default);
    Task<IReadOnlyList<AiMessageDocument>> GetMessages(MessageQuery query, CancellationToken ct = default);
    Task<IReadOnlyList<MessageSearchHit>> SearchMessages(MessageSearchQuery query, CancellationToken ct = default);

    Task Purge(DateTimeOffset before, CancellationToken ct = default);
}
```

## Implementation rules

| Method | Must |
|---|---|
| `CreateSession` | throw when the id already exists |
| `SaveSession` | replace the header **only if** the stored `Version` equals `expectedVersion`, otherwise throw `SessionConflictException`. The caller has already set the new version on the document |
| `QuerySessions` | filter by `Text` (title / summary), `From` / `To` (last activity), `Tags`, `Profile`; order by `LastActivity` descending; apply `Skip` / `Take` |
| `DeleteSession` | delete the header and all of its messages |
| `AppendMessage` | allocate `Sequence` (unique and increasing per session) and return the message with it set |
| `UpdateMessage` | replace the message with the same `MessageId` |
| `GetMessages` | return messages in sequence order; with a `Limit` and `BeforeSequence` (or no cursor), the **newest** `Limit` before the cursor; with `AfterSequence`, the oldest after it; honour `IncludeCompacted` |
| `SearchMessages` | rank user and assistant message `Text` against the query; skip sessions with `Settings.ExcludeFromSearch`; honour `SessionId`, `ExcludeSessionId`, `From` / `To` and `ExcludeFromSequence` |
| `Purge` | delete sessions whose last activity is before the date |

The version check and the sequence allocation are what make two live instances of one session safe. See [Architecture](/aiconversation/architecture#two-instances-of-one-session). A store backed by a database should do both atomically (a conditional update or a transaction).

## Serialization

Serialize documents with the source-generated `AiConversationJsonContext`. It is AOT and trim safe, writes camel-case names and string enums, and handles the `MessagePart` hierarchy:

```csharp
var json = JsonSerializer.Serialize(message, AiConversationJsonContext.Default.AiMessageDocument);
var header = JsonSerializer.Deserialize(json, AiConversationJsonContext.Default.AiSessionDocument);
```

Every document has a `SchemaVersion`, so a store can migrate older rows when it reads them.

For search, the public `SearchText` helper splits a query into terms (punctuation, possessives and common stop words removed) and builds a snippet around the first match, which is what the built-in stores use.

## Reading history

Apps read history through the session rather than the store:

```csharp
var page = await session.GetMessages(beforeSequence: null, count: 30);   // newest page
var older = await session.GetMessages(page.Messages[0].Sequence, 30);
```

:::note[Coming from 2.x]
`IMessageStore`, `AiChatMessage` and `ChatMessageDirection` are gone. Version 2 history has no sessions and is not imported; v3 starts fresh.
:::
