---
title: Acknowledgements & Sound
description: How voice replies are delivered - speech, brief speech, sound cues or silence - and the "one moment" acknowledgement for slow tools
---

`VoiceOptions.Acknowledgement` controls how the [voice conversation](/aiconversation/voice) delivers replies, from silent text-only to full text-to-speech.

```csharp
await voice.Attach(session, new VoiceOptions { Acknowledgement = AiAcknowledgement.LessWordy });
```

| `AiAcknowledgement` | Speech | Sound cues | Notes |
|---|---|---|---|
| `None` | no | no | voice in, text out: replies only appear in the session (and the chat UI) |
| `AudioBlip` | no | yes | short cues at state changes, including `Respond` when the reply starts |
| `LessWordy` | yes | yes | each voice turn asks the model to be brief |
| `Full` *(default)* | yes | yes | the full reply is spoken |

## Brief replies

In `LessWordy` mode every voice turn carries an extra system instruction, `VoiceOptions.LessWordyInstruction` ("Be concise and brief in your responses…"). It's sent with [`AiInput.Instructions`](/aiconversation/#turns), so it applies to that turn only and is never stored in the history.

The same mechanism is available to your own code:

```csharp
session.Send(AiInput.Text("Summarize this").WithInstructions("Answer in one sentence."));
```

## "One moment" for slow tools

When the model calls a tool before it has said anything, silence can sound like a hang. The voice conversation speaks `VoiceOptions.ToolAcknowledgement` ("One moment.") once, then the reply as usual. Set it to `null` to turn this off.

Tools registered with `AiToolFlags.Silent` never trigger it. The built-in `ask_user`, `memory`, conversation search and voice-listing tools are all silent:

```csharp
opts.AddTool(myLookupTool, AiToolFlags.Silent);
```

The acknowledgement isn't part of the reply: it isn't recorded as spoken text if the user interrupts.

## Sound cues

Cues play at state changes unless `Acknowledgement` is `None`:

| `AiAction` | When |
|---|---|
| `Ok` | the microphone starts listening (push-to-talk, wake word, follow-up) |
| `Think` | the utterance was sent to the model |
| `Respond` | the reply starts (`AudioBlip` mode only, since it isn't spoken) |
| `Cancel` | a quiet word or `StopSpeaking` stopped the reply |
| `Error` | a turn or recognition error |

The built-in `DefaultSoundProvider` plays embedded WAV files through `IAudioPlayer` (and does nothing if no player is registered). Replace it with your own:

```csharp
public class MySounds(IAudioPlayer player) : ISoundProvider
{
    public Task Play(AiAction action) => action switch
    {
        AiAction.Ok => player.PlayAsync("ding.wav"),
        _ => Task.CompletedTask
    };
}

builder.Services.AddShinyAiConversationVoice(v => v.SetSoundProvider<MySounds>());
```

Sound playback failures are logged and never stop the conversation.
