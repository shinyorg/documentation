## Registration

```csharp
builder.Services.AddBluetoothLE();
builder.Services.AddBleHubClient<IGameHub>(ServiceUuid, GameHubCharacteristicUuid);
```

This registers the **generated proxy** (`GameHubClient` for `IGameHub`) as a singleton. Inject whichever shape you
prefer:

| Inject | You get |
|---|---|
| `IBleHubClient<IGameHub>` | Connection management, plus `.Hub` for calls and events (easiest to mock) |
| `GameHubClient` | The concrete generated proxy |
| `IGameHub` | Calls and events only |

## Discover & Connect

```csharp
public partial class JoinViewModel(IBleHubClient<IGameHub> client) : ObservableObject
{
    IDisposable? scan;
    public ObservableCollection<BleHubHostInfo> Hosts { get; } = new();

    public void OnAppearing() => this.scan = client
        .Discover()   // scans for the hub's service UUID - dispose to stop
        .Subscribe(host => MainThread.BeginInvokeOnMainThread(() =>
        {
            if (!this.Hosts.Any(x => x.Id == host.Id))
                this.Hosts.Add(host);    // host.Name (advertised), host.Rssi
        }));

    [RelayCommand]
    async Task Join(BleHubHostInfo host)
    {
        this.scan?.Dispose();
        await client.Connect(host, new BleHubConnectOptions(
            Name: "Allan",
            AppVersion: AppInfo.Current.VersionString,
            Properties: new() { ["team"] = "blue" }
        ));
        var result = await client.Hub.Join("Allan", null);
    }
}
```

`Connect` does the following:
1. Connects to the host.
2. Requests the largest MTU the platforms allow.
3. Subscribes for pushes.
4. Completes the handshake.

The host may refuse the client: it is full, `ValidateClient` said no, or the hub isn't running. In that case
`Connect` throws a `BleHubException` with the reason.

| Member | |
|---|---|
| `Status` | `Disconnected`, `Connecting`, `Connected`, `Disconnecting` |
| `StatusChanged` / `Connected` / `Disconnected` | `Disconnected` carries a [`HubDisconnect`](#disconnect-reasons) saying why. `StatusChanged` carries it as `Disconnect` while `Disconnecting` and `Disconnected` |
| `Host` / `HostName` | The connected host, and its name: from the handshake, kept up to date when the host [renames](#renaming) |
| `ClientName` | The name the host knows you by: `BleHubConnectOptions.Name`, or your latest `Rename`. `null` while disconnected |
| `CanTransferFiles` | See [File Transfers](./files) |
| `Disconnect()` | Leaves the hub, telling the host first |
| `Rename(name)` / `HostRenamed` | See [Renaming](#renaming) |

## Renaming

Change the name the host knows you by without reconnecting:

```csharp
try
{
    await client.Rename("Allan B");
}
catch (BleHubRemoteException ex) when (ex.RemoteErrorType == BleHubRemoteException.RenameRefused)
{
    this.Show(ex.Message);   // the host said no - client.ClientName is unchanged
}
```

- The host checks the new name with `ValidateClient`, then runs the hub's
  [`OnRenamedAsync`](./hosting#renaming). Either can refuse.
- Renaming to the current name does nothing. Renaming while disconnected throws `BleHubDisconnectedException`.
- A later `Connect` uses the name in its own `BleHubConnectOptions`.
- A host older than renames refuses with a `BleHubRemoteException` too.

When the host renames itself, `HostRenamed` is raised with the new name. `HostName` is already updated, and the event
arrives in order with the hub's events, on the same background thread.

```csharp
client.HostRenamed += (_, name) => MainThread.BeginInvokeOnMainThread(() => this.Title = name);
```

## Disconnect Reasons

`Disconnected` is an `EventHandler<HubDisconnect>`. `Reason` is a `HubDisconnectReason` you can switch on, `Message` is
the host's text (from `Abort`, `Stop` or `Disconnect`) if it gave one, and `Description` is the message or a default
text for the reason.

```csharp
client.Disconnected += (_, disconnect) =>
{
    var text = disconnect.Reason switch
    {
        HubDisconnectReason.ServerShutdown => "The host closed the game",
        HubDisconnectReason.ServerDisconnect => disconnect.Message ?? "You were removed from the game",
        HubDisconnectReason.ClientTimeout => "Lost the connection to the host",
        _ => null   // ClientDisconnect - we left
    };
    if (text != null)
        MainThread.BeginInvokeOnMainThread(() => this.Show(text));
};
```

| `HubDisconnectReason` | When |
|---|---|
| `ClientDisconnect` | You called `Disconnect()` or disposed the client |
| `ClientTimeout` | The link to the host dropped |
| `ServerDisconnect` | The host disconnected this client (`Context.Abort` or `IHubContext.Disconnect`). A disconnect from an older host that doesn't send a reason also arrives as this |
| `ServerShutdown` | The host stopped the hub, or stopped hosting |
| `ConnectionFailed` | `Connect` or the handshake failed. `Disconnected` isn't raised, because the client never connected. `StatusChanged` still reports it |

## Calls

```csharp
var result = await client.Hub.MakeMove(4);
await client.Hub.Rematch();

using var cts = new CancellationTokenSource();
await foreach (var n in client.Hub.Countdown(10, cts.Token))
{
    if (n == 3)
        break;   // cancels the hub method on the host
}
```

- **Concurrent calls** are fine. Each is matched to its own reply.
- **Timeouts**: a call that gets no reply within `BleHubProtocolOptions.RequestTimeout` (30s by default) throws a
  `TimeoutException`. Streams aren't timed out.
- **Cancellation**: cancelling a call's `CancellationToken` stops waiting and cancels the hub method on the host.

```csharp
builder.Services.ConfigureBleHubProtocol(o => o.RequestTimeout = TimeSpan.FromSeconds(10));
```

## Events (pushes)

```csharp
client.Hub.StateChanged += state => MainThread.BeginInvokeOnMainThread(() => this.Apply(state));
client.Hub.Emote += (from, emoji) => MainThread.BeginInvokeOnMainThread(() => this.Show($"{from} {emoji}"));
```

Events are raised on a **background thread**, one at a time and **in the order the host sent them**. Marshal to the
UI thread yourself.

## Failures

| Exception | When |
|---|---|
| `BleHubRemoteException` | The hub method threw. Includes `RemoteErrorType` and `Message` |
| `BleHubDisconnectedException` | You called while not connected, or the connection dropped while a call was in flight (`Disconnect` says why, and `Reason` is its text) |
| `TimeoutException` | No reply within `RequestTimeout` |
| `OperationCanceledException` | You cancelled the call |

## Several Hubs on One Host

Register a client per hub contract. Connecting each to the same host shares **one** BLE connection, which is reference
counted, so disconnecting one hub client leaves the others connected.

```csharp
builder.Services.AddBleHubClient<IGameHub>(ServiceUuid, GameHubCharacteristicUuid);
builder.Services.AddBleHubClient<IChatHub>(ServiceUuid, ChatHubCharacteristicUuid);
```
