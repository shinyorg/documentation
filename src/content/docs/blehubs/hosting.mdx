## Registration

```csharp
builder.Services.AddBluetoothLeHosting();

builder.Services.AddBleHub<GameHub>(ServiceUuid, GameHubCharacteristicUuid, o =>
{
    o.MaxClients = 6;   // default 8, null = unlimited
    o.ValidateClient = info => String.IsNullOrWhiteSpace(info.Name) ? "A player name is required" : null;
});

builder.Services.ConfigureBleHubHost(o =>
{
    o.LocalName = "TTT";   // advertised name - keep it short
});
```

- Every hub needs **its own characteristic UUID**. Use full 128-bit UUIDs.
- Hubs should **share one service UUID**. Each extra 128-bit UUID in the advertisement eats 18 of its 31 bytes.
- `ValidateClient` sees the client's handshake (`Name`, `AppVersion`, `Properties`). Return a reason to refuse the
  client, or `null` to accept it.

## Writing a Hub

```csharp
public class GameHub(GameEngine engine) : BleHub<IGameHub>
{
    public override async Task OnConnectedAsync()
        => await this.Groups.AddToGroupAsync(this.Context.ConnectionId, "lobby");

    public override async Task OnDisconnectedAsync(HubDisconnect disconnect)
    {
        engine.Leave(this.Context.ConnectionId);   // disconnect.Reason says why - see Disconnect Reasons below
        await this.Clients.All.StateChanged(engine.Snapshot());
    }

    public async Task<MoveResult> MakeMove(int cell)
    {
        var error = engine.TryMove(this.Context.ConnectionId, cell);
        if (error != null)
            return new MoveResult(false, error);

        await this.Clients.All.StateChanged(engine.Snapshot());
        return new MoveResult(true, null);
    }

    // the contract's CancellationToken may be taken (as the last parameter) or left out
    public async IAsyncEnumerable<int> Countdown(int from, [EnumeratorCancellation] CancellationToken ct)
    {
        for (var i = from; i > 0; i--)
        {
            yield return i;
            await Task.Delay(1000, ct);
        }
    }
    ...
}
```

:::caution
A **new hub instance** is created, in its own DI scope, for **every call**, just like SignalR. Never keep state in hub
fields. Use singletons, or `Context.Items` for per-connection state.
:::

### Context

| Member | |
|---|---|
| `ConnectionId` | The caller's id |
| `Client` | `Name`, `AppVersion`, `Properties`, `Mtu`, `ConnectedAt`, `Items`, and `Peripheral`: the BLE central (`IPeripheral`), null for a client connected over another transport |
| `Items` | Per-connection state, kept while the client is connected |
| `ConnectionAborted` | Cancelled when the client goes away |
| `Abort(reason)` | Asks the client to leave. Called from a hub method, it takes effect **after** that method's reply is sent |

### Clients

| Target | Who |
|---|---|
| `All` | Everyone connected |
| `Caller` / `Others` | The caller / everyone except the caller |
| `Client(id)` / `Clients(ids)` | Specific connections |
| `AllExcept(ids)` | Everyone but these |
| `Group(name)` / `Groups(names)` | Group members |
| `GroupExcept(name, ids)` / `OthersInGroup(name)` | Group members, minus some |

Every target exposes the contract's events as methods (`Clients.Others.Emote("host", "👋")`).

### Groups

`Groups.AddToGroupAsync(connectionId, name)`, `RemoveFromGroupAsync`, and `GetMembers(name)`. When a client leaves,
its memberships are removed automatically, after `OnDisconnectedAsync` has run.

### Disconnect Reasons

`OnDisconnectedAsync(HubDisconnect disconnect)` tells you why a client left. `disconnect.Reason` is a
`HubDisconnectReason` you can switch on, `disconnect.Message` is the optional text passed to `Abort`, `Stop` or
`Disconnect`, and `disconnect.Description` is the message or a default text for the reason.

| `HubDisconnectReason` | When |
|---|---|
| `ClientDisconnect` | The client called `Disconnect()` or was disposed. It tells the host before it unsubscribes |
| `ClientTimeout` | The link dropped: an unsubscribe with no goodbye first (iOS and Android report a vanished client this way), or the cleanup sweep |
| `ServerDisconnect` | `Context.Abort(reason)` or `IHubContext.Disconnect(id, reason)` |
| `ServerShutdown` | `IBleHubHost.Stop(reason)` or `IHubContext.Stop(reason)` |

```csharp
public override Task OnDisconnectedAsync(HubDisconnect disconnect)
{
    if (disconnect.Reason == HubDisconnectReason.ClientTimeout)
        engine.HoldSeat(this.Context.ConnectionId);   // the link dropped - they may come back
    else
        engine.Leave(this.Context.ConnectionId);
    return Task.CompletedTask;
}
```

By default `OnDisconnectedAsync(HubDisconnect)` calls `OnDisconnectedAsync(string? reason)` with `Description`, so
hubs that override the string version keep working. Override one or the other.

### Renaming

A connected client can change its name with `client.Rename(name)`, without reconnecting. The host runs `ValidateClient`
with the new name (and the client's original `AppVersion` and `Properties`), then the hub's `OnRenamedAsync`:

```csharp
public override Task OnRenamedAsync(string? previousName)
{
    if (engine.IsTaken(this.Context.Client.Name))
        throw new InvalidOperationException("That name is taken");   // refused - the client keeps its old name

    return this.Clients.Others.PlayerRenamed(previousName, this.Context.Client.Name);
}
```

- `Context.Client.Name` already has the new name. Throwing puts the old one back, and the client gets a
  `BleHubRemoteException` (of type `BleHubRemoteException.RenameRefused`) with your message.
- A client's renames run one at a time.
- **Other clients aren't told automatically.** Push it yourself, as above, if they need to know.
- `IHubContext<THub>.ClientRenamed` is raised after a rename is accepted, with
  `BleHubClientRenamedEventArgs(Client, PreviousName)`.

### Errors

An exception thrown by a hub method is sent back to the caller as a `BleHubRemoteException` (with `RemoteErrorType` and
`Message`). The connection stays up.

## Outside a Hub: IHubContext

Inject `IHubContext<THub>` anywhere: services, view models, timers.

```csharp
public class Lobby(IHubContext<GameHub> hub)
{
    public Task Open() => hub.Start();                          // start just this hub
    public Task Close() => hub.Stop("The lobby is closed");     // clients get the reason
    public bool IsOpen => hub.IsRunning;

    public Task Broadcast(GameState state) => hub.Clients.All.StateChanged(state);
    public Task Kick(string connectionId) => hub.Disconnect(connectionId, "Removed by host");

    public IReadOnlyList<BleHubConnectedClient> Players => hub.ConnectedClients;
}
```

`IHubContext<THub>` also has `Groups` and the `ClientConnected` / `ClientDisconnected` / [`ClientRenamed`](#renaming) events. `ClientDisconnected`
raises `BleHubClientDisconnectedEventArgs(Client, Disconnect)`. `e.Disconnect` is the [`HubDisconnect`](#disconnect-reasons),
and `e.Reason` is its `Description`.

## Starting & Stopping

| | |
|---|---|
| `IBleHubHost.Start()` / `Stop(reason)` | Every registered hub |
| `IHubContext<THub>.Start()` / `Stop(reason)` | Just that hub |
| `IBleHubHost.Rename(localName)` | Changes the host's name without stopping anything |

- **Stopping a hub** tells its clients to disconnect (they receive `ServerShutdown` and the reason) and refuses new
  clients with "Hub is not running".
- **Shared services**: hubs that share a service UUID live in one GATT service. It stays up while any of them is
  running, so stopping one hub never drops another hub's clients.
- **Advertising** always lists exactly the services that have a running hub, and stops when none do.
- **Renaming the host**: `IBleHubHost.Rename("TTT 2")` sets `LocalName`, re-advertises under the new name while hubs
  are running, and tells every connected client (their `HostName` updates and `HostRenamed` is raised). While stopped,
  it just sets the name the next `Start` uses.
- **Shared resources**: BLE access, the [file server](./files) and the cleanup sweep start with the first running hub
  and stop with the last.

:::note[Disconnecting is cooperative]
iOS can't force a central (client) off a peripheral (host). So `Stop`, `Disconnect` and `Abort` **ask** the client to
leave, and the client library always complies. A client that silently drops is removed when it unsubscribes, or by a
periodic sweep (`BleHubHostOptions.ClientSweepInterval`, 10s by default).
:::
