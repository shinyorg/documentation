## v1

### 1.0 - TBD
<RN type="feature">Initial release - SignalR style hubs over Bluetooth LE. A `[BleHubClient]` interface describes the hub: its methods (`Task`, `Task<T>`, `IAsyncEnumerable<T>`) are client to host calls and its `Action` events are host to client pushes</RN>
<RN type="feature">Source generator emits the client proxy, the hub dispatcher, typed pushes (`Clients.All.StateChanged(state)`) and an `IHubContext<THub>.Clients` extension property - AOT and trim safe, no reflection, with `SBH001`-`SBH006` diagnostics</RN>
<RN type="feature">`BleHub<TContract>` with `Context`, `Clients` (All, Others, Caller, Client, Group...), `Groups`, `OnConnectedAsync` / `OnDisconnectedAsync` and `Context.Abort()`</RN>
<RN type="feature">`IHubContext<THub>` to push, disconnect clients and start / stop a single hub from outside a hub - shared GATT services stay up while any of their hubs runs and advertising follows the running hubs</RN>
<RN type="feature">Generated client proxies with discovery, MTU negotiation, timeouts, cancellation that reaches the hub, ordered push delivery and shared BLE connections across hub clients</RN>
<RN type="feature">L2CAP file transfers - `UploadFile`, `UploadStream` and `DownloadFile` on the client, a directory backed or custom (`IBleHubFileHandler`) server on the host</RN>
<RN type="feature" breaking>Typed disconnect reasons - `HubDisconnect` (`Reason`, `Message`, `Description`) with `HubDisconnectReason`: `ClientDisconnect`, `ClientTimeout`, `ServerDisconnect`, `ServerShutdown` and `ConnectionFailed`. Hubs can override `OnDisconnectedAsync(HubDisconnect)` (`OnDisconnectedAsync(string? reason)` still works), and the client now tells the host it is leaving before it unsubscribes, so the host can tell a client that left from a dropped link. Breaking: `IBleHubConnection.Disconnected` is now `EventHandler<HubDisconnect>`, and `BleHubClientDisconnectedEventArgs`, `BleHubStatusChangedEventArgs` and `BleHubDisconnectedException` carry a `HubDisconnect` (their `Reason` string is computed from it). The wire stays compatible with older hosts and clients</RN>
<RN type="feature">`BleHubConnectedClient.Peripheral` - the BLE central a client is connected through (null for a client on another transport)</RN>
<RN type="chore">Built on Shiny.BluetoothLE / Shiny.BluetoothLE.Hosting 5.9 (beta), which fixes L2CAP file transfers whenever an iOS device is the host or the client</RN>
