BluetoothLE Hosting allows your device to act as a BLE peripheral (server). You can advertise services, create GATT services with characteristics, and communicate with central devices that connect to you.

## Features

- Advertise as a BLE peripheral
- Create GATT services with read/write/notify characteristics via the imperative `AddService` builder
- iBeacon broadcasting
- L2CAP CoC channel listeners for high-throughput streaming, including a [directory-backed file server](./l2cap#l2cap-file-server) centrals can upload to and download from
- Cross-platform: iOS, macOS, Android, Linux (Windows hosting is currently stubbed)

## Platform Notes

| Feature | iOS | macOS | Android | Windows | Linux |
|---------|-----|-------|---------|---------|-------|
| Advertising | Foreground + limited background | Full | Full | — | Full (BlueZ) |
| GATT Server | Full | Full | Full | — | Full (BlueZ) - see [notification limits](./gatt) |
| [L2CAP CoC](./l2cap) | Full | Full | API 29+ | — | Full (BlueZ socket) |

:::caution[iOS]
On iOS, advertising is limited when the app is in the background. The local name is not included and only service UUIDs are advertised.
:::

:::caution[Blazor WebAssembly]
BLE peripheral / GATT server hosting is **not possible in the browser**. The Web Bluetooth API only exposes the central role — there is no spec or browser implementation for advertising as a peripheral. This isn't a Shiny limitation; it cannot be worked around with JS interop.
:::

## Advertising

```csharp
// Start advertising with a local name and service UUIDs
await hostingManager.StartAdvertising(new AdvertisementOptions(
    LocalName: "MyDevice",
    ServiceUuids: new[] { "Your-Service-UUID" }
));

// Check advertising state
var isAdvertising = hostingManager.IsAdvertising;

// Stop advertising
hostingManager.StopAdvertising();
```

Everything except the local name has to fit the **31-byte** advertising packet, together with the 3-byte flags the
platform adds. `StartAdvertising` measures the options before touching the radio and throws an `ArgumentException`
listing each section's size when they don't fit. In practice that means **one custom 128-bit service UUID at most**:
two are 37 bytes with the flags. Advertise the UUID centrals filter on, and let them discover the rest of your
services from the GATT server once they connect. 16-bit SIG UUIDs take 2 bytes each.

| Section | Bytes |
| --- | --- |
| Flags | 3 (always on Apple and Windows; on connectable advertisements on Android and Linux) |
| Service UUID list | 2, plus 2 per 16-bit, 4 per 32-bit or 16 per 128-bit UUID |
| Service data entry | 2 + UUID + payload |
| Manufacturer data | 2 + 2 (company ID) + payload |
| Tx power | 3 (Android and Linux, when `IncludeTxPower` is set) |
