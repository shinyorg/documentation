The Bluetooth LE bridge scans for peripherals, connects, lists services and characteristics, reads and writes them, and streams notifications to the page as events. It's backed by Shiny.BluetoothLE.

Android, iOS, Mac Catalyst, macOS (AppKit) and Windows. Linux answers `501`.

## Install and register

```bash
dotnet add package Shiny.AppDeviceBridge.BluetoothLE
```

```csharp
builder.UseAppDeviceBridge(
    bridge => bridge.AddBluetoothLEBridge(),
    webApp => { /* … */ }
);
```

| Client | C# | TypeScript |
| --- | --- | --- |
| `IBluetoothLEBridge` | `AddBluetoothLEBridgeClient()` | `BluetoothLEBridge` |

## Routes and events

| Bridge | Routes | Events |
| --- | --- | --- |
| Bluetooth LE | `GET ble/status`, `POST ble/access`, `POST/DELETE ble/scan`, `GET ble/peripherals[/{uuid}]`, `POST/DELETE …/connection`, `GET …/rssi`, `GET …/services`, `GET …/characteristics`, `GET/PUT …/characteristics/{c}`, `POST/DELETE …/notifications` | `ble.scan`, `ble.status`, `ble.notification`, `ble.error` |

A scan and a characteristic subscription run only while something listens to their events: starting one without a listener answers `409` `not_listening`, so subscribe first — see [Events](/appdevicebridge/bridges/#events). Platform setup is Shiny.BluetoothLE's: `NSBluetoothAlwaysUsageDescription` on Apple platforms, `BLUETOOTH_SCAN` and `BLUETOOTH_CONNECT` (location before Android 12) on Android.

## Security

These routes sit under `AppDeviceBridgePolicies.Bridges` like every other bridge: callers on this device by default.
See [Security](/appdevicebridge/security/).
