The Bluetooth LE bridge scans for peripherals, connects, lists services and characteristics, reads and writes them, and streams notifications to the page as events. It's backed by Shiny.BluetoothLE.

Android, iOS, Mac Catalyst, macOS (AppKit) and Windows. Linux answers `501`.

## Install and register

```bash
dotnet add package Shiny.AppDeviceBridge.BluetoothLE
```

```csharp
builder.UseAppDeviceBridge(
    bridge => bridge.AddBluetoothLEBridge(),
    webApp => { /* … */ }
);
```

| Client | C# | TypeScript |
| --- | --- | --- |
| `IBluetoothLEBridge` | `AddBluetoothLEBridgeClient()` | `BluetoothLEBridge` |

## From the page

Listen before you start: a scan and a characteristic subscription run only while something listens to their events,
and starting one without a listener answers `409` `not_listening` — see [Events](/appdevicebridge/bridges/#events).
Characteristic values travel as base64 in JSON.

```ts
import { BluetoothLEBridge } from "@shinyorg/appdevicebridge";

const ble = new BluetoothLEBridge();
const status = await ble.requestAccess();

const stopScan = await ble.onScanResult(r => console.log(r.uuid, r.name, r.rssi));
await ble.startScan({ serviceUuids: ["180D"] });           // heart rate
// …the user picks one
stopScan();                                               // the scan stops once nothing listens

const peripheral = await ble.connect(uuid, { timeoutMs: 10_000 });
const value = await ble.read(uuid, "180A", "2A29");       // manufacturer name, base64

await ble.onNotification(n => render(atob(n.data ?? "")));
await ble.startNotifications(uuid, "180D", "2A37");
```

Platform setup is Shiny.BluetoothLE's: `NSBluetoothAlwaysUsageDescription` on Apple platforms, `BLUETOOTH_SCAN` and
`BLUETOOTH_CONNECT` (location before Android 12) on Android.
