The OBD-II bridge talks to a vehicle through an ELM327 or OBDLink adapter: decoded PIDs, the VIN, trouble codes and live readings. It's backed by Shiny.Obd.

## Install and register

```bash
dotnet add package Shiny.AppDeviceBridge.Obd
```

```csharp
builder.UseAppDeviceBridge(
    bridge => bridge.AddObdBridge(),
    webApp => { /* … */ }
);
```

| Client | C# | TypeScript |
| --- | --- | --- |
| `IObdBridge` | `AddObdBridgeClient()` | `ObdBridge` |

## Details

| Topic | Details |
| --- | --- |
| **Adapters** | ELM327 and OBDLink, one at a time. `scan` finds Bluetooth LE adapters, or with `"transport": "wifi"` probes the addresses Wi-Fi adapters ship with. `connection` takes the `peripheralUuid` from a scan, or a Wi-Fi `host` and `port`. The host must be a loopback, private or link-local IP address. |
| **Reading** | `command` takes a name from `GET obd/commands` (`engineRpm`, `vehicleSpeed`, `coolantTemperature`…) and answers the decoded value with its unit. `POST obd/raw` sends a read-only request: modes 01, 02, 03, 05, 06, 07, 09, 0A or 22, or an informational AT command. Commands are serialized, because ELM327 is half-duplex. |
| **Trouble codes** | `GET obd/dtc` returns stored, pending and permanent codes. A list is `null` when the vehicle doesn't support that mode. `DELETE obd/dtc` needs `?confirm=true`, because clearing codes also resets the emissions readiness monitors. |
| **Monitoring** | `monitor` polls up to 10 commands, every 250 ms at most often, and sends each result as `obd.reading`, so listen to that first; without a listener it answers `409`. It stops once nothing listens to `obd.reading`, and the adapter stays connected. After three rounds with no answers the connection is dropped with `obd.disconnected`. |
| **Platform setup** | Bluetooth as for the Bluetooth LE bridge. Wi-Fi adapters need `NSLocalNetworkUsageDescription` on iOS and Mac Catalyst. On Android, the app has to bind to the adapter's network, which has no internet. Linux supports Wi-Fi adapters only. |

## From the page

```ts
import { ObdBridge } from "@shinyorg/appdevicebridge";

const obd = new ObdBridge();
const [adapter] = await obd.scan({ transport: "Ble", scanMs: 5000 });
await obd.connect({ transport: "Ble", peripheralUuid: adapter.id });

const rpm = await obd.read({ command: "engineRpm" });      // { value: 812, unit: "rpm" }
const { vin } = await obd.getVin();

// live gauges: listen, then start the monitor
await obd.onReading(r => gauges[r.command] = r.value);
await obd.startMonitor({ commands: ["engineRpm", "vehicleSpeed", "coolantTemperature"], intervalMs: 500 });
```

`getCommands()` lists the named values `read` and `startMonitor` take.
