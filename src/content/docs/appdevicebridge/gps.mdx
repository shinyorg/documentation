The GPS bridge gives the page permissions, the current and last position, and a listener whose readings arrive as `gps.reading` events and at background.js. The motion bridge, in the same package, reports walking, running, cycling, driving or stationary, and the geocoding bridge turns a position into an address. Both are backed by Shiny.Gps.

GPS works on Android, iOS, Mac Catalyst and Windows; motion activity on Android, iOS and Mac Catalyst. Everywhere else they answer `501`. For the page's own position, `navigator.geolocation` with `AllowWebPermissions(WebAppWebPermissions.Geolocation)` works on every head except Linux, and needs no bridge — see [Hosting](/appdevicebridge/hosting/#camera-microphone-and-location-in-the-page).

## Install and register

```bash
dotnet add package Shiny.AppDeviceBridge.Gps
```

```csharp
builder.UseAppDeviceBridge(
    bridge => bridge.AddGpsBridge().AddMotionActivityBridge().AddGeocodingBridge(),
    webApp => { /* … */ }
);
```

| Client | C# | TypeScript |
| --- | --- | --- |
| `IGpsBridge` | `AddGpsBridgeClient()` | `GpsBridge` |
| `IMotionBridge` | `AddMotionBridgeClient()` | `MotionBridge` |
| `IGeocodingBridge` | `AddGeocodingBridgeClient()` | `GeocodingBridge` |

## Motion activity

Walking, running, cycling, driving or stationary, from the OS's activity recognition.
There's no history, only the latest reading and live ones. It ships in `Shiny.AppDeviceBridge.Gps`, but `AddGpsBridge()` doesn't include it,
because it needs its own setup: `NSMotionUsageDescription` on iOS (the permission request crashes without it),
and `ACTIVITY_RECOGNITION` with Google Play Services on Android. Other platforms return `501`.

GPS and motion listeners keep running without a page, because background.js receives their readings too — see [Native Calls & Background](/appdevicebridge/background/).

## Reverse geocoding

The addresses at a position, from the platform geocoder: MapKit / CoreLocation on iOS and Mac Catalyst, and
`android.location.Geocoder` on Android. Windows, Linux, macOS and Android devices without a geocoding backend (typically
no Google Play services) use OpenStreetMap's Nominatim instead, so it works on every platform. It needs network access but
no location permission, which is why `AddGpsBridge()` doesn't include it: add `AddGeocodingBridge()` when you want it.

The public Nominatim server allows one request a second and asks for a User-Agent that identifies your app; it defaults to
your entry assembly's name and version. To use your own server, or another User-Agent, register the geocoder first, and
the bridge keeps it:

```csharp
builder.Services.AddGeocoding(o => o.BaseUri = new Uri("https://nominatim.example.com/"));
```

Display OpenStreetMap's attribution wherever Nominatim results appear.

```ts
import { GeocodingBridge } from "@shinyorg/appdevicebridge";

const [place] = await new GeocodingBridge().reverseGeocode(43.6426, -79.3871);
console.log(place?.formattedAddress);   // most relevant first; empty when nothing was found
```

## From the page

```ts
import { GpsBridge } from "@shinyorg/appdevicebridge";

const gps = new GpsBridge();
const settings = { backgroundMode: "None", requestPreciseAccuracy: true, autoRestart: true } as const;

const { access } = await gps.requestAccess(settings);
if (access !== "Available") return;

const here = await gps.getCurrentPosition();               // one fix, or null

await gps.onReading(r => console.log(r.latitude, r.longitude, `±${r.positionAccuracy} m`));
await gps.startListener(settings);                         // 409 when another listener runs
```

Only one listener runs at a time, and it belongs to the app, not the page — `getListener()` says what's running.
