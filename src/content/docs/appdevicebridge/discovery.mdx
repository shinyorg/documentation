The discovery bridge finds and advertises services on the local network over mDNS/Bonjour, SSDP/UPnP and WS-Discovery, backed by Shiny.Net.Discovery.

## Install and register

```bash
dotnet add package Shiny.AppDeviceBridge.Discovery
```

```csharp
builder.UseAppDeviceBridge(
    bridge => bridge.AddDiscoveryBridge(DiscoveryProtocols.All),
    webApp => { /* … */ }
);
```

| Client | C# | TypeScript |
| --- | --- | --- |
| `IDiscoveryBridge` | `AddDiscoveryBridgeClient()` | `DiscoveryBridge` |

## Details

- **Searching:** `search` returns everything seen during `scanMs`, 5 s by default and 30 s at most.
- **Browsing:** each `browse` streams results as `discovery.mdns`, `discovery.ssdp` or `discovery.wsd`, so listen to
  that event first; without a listener it answers `409`. At most 8 run at once, and a protocol's browses stop once
  nothing listens to its event.
- **Publishing:** `publications` keep advertising until deleted. At most 16.
- **Platform setup:** on iOS and Mac Catalyst, list every browsed service type in `NSBonjourServices`
  and set `NSLocalNetworkUsageDescription`. On Android, SSDP and WS-Discovery need
  `CHANGE_WIFI_MULTICAST_STATE`.

## From the page

A search collects answers for `scanMs` and returns them; a browse keeps going and streams them as events until you
stop it or nothing listens any more.

```ts
import { DiscoveryBridge } from "@shinyorg/appdevicebridge";

const discovery = new DiscoveryBridge();

// one-shot: every printer that answers within 3 seconds
const printers = await discovery.searchMdns({ serviceType: "_ipp._tcp", resolveServices: true, scanMs: 3000 });

// continuous: services as they come and go
await discovery.onMdns(r => r.status === "Found" ? add(r.service) : remove(r.service));
const browse = await discovery.browseMdns({ serviceType: "_http._tcp" });

// later
await discovery.stopBrowse(browse.id);
```
