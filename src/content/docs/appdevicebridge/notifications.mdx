The notifications bridge sends local notifications now, on a schedule, repeating or at a geofence, lists and cancels pending ones, sets the badge and manages channels. A tap reaches the page, or background.js when no page is open. It's backed by Shiny.Notifications.

Android, iOS, Mac Catalyst, macOS, Windows, and Linux through Shiny.Notifications.Linux.

## Install and register

```bash
dotnet add package Shiny.AppDeviceBridge.Notifications
```

```csharp
builder.UseAppDeviceBridge(
    bridge => bridge.AddNotificationsBridge(),
    webApp => { /* … */ }
);
```

| Client | C# | TypeScript |
| --- | --- | --- |
| `INotificationsBridge` | `AddNotificationsBridgeClient()` | `NotificationsBridge` |

## Routes and events

| Bridge | Routes | Events |
| --- | --- | --- |
| Notifications | `GET notifications`, `POST notifications/access`, `POST notifications/send`, `GET notifications/pending`, `DELETE notifications[?scope=]`, `DELETE notifications/{id}`, `GET/PUT notifications/badge`, `GET/POST notifications/channels`, `DELETE notifications/channels/{id}` | `notification.entry`, `notification.received` |

What `send` takes, and how taps reach background.js, is on [Native Calls & Background](/appdevicebridge/background/).

## Security

These routes sit under `AppDeviceBridgePolicies.Bridges` like every other bridge: callers on this device by default.
See [Security](/appdevicebridge/security/).
