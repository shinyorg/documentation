## Commercial support

Community support stays free for everyone. When a project is heading to production, and especially
when it depends on background BLE, background jobs, GPS and geofencing, push, large transfers or offline
sync, the problems get platform-specific. Those are the problems commercial support is for.

It comes from [ShinySoft Technologies](https://shinysoft.biz), the company that builds and maintains the
Shiny libraries. The person who answers your ticket is the person who can fix the library.

### What's included

| | |
| :--- | :--- |
| **Priority issue response** | Your issues go to the front of the queue, in public or private, and fixes ship on a timeline you can plan around. |
| **Support agreement (SLA)** | Response targets and escalation agreed in writing for your team and the platforms you ship on. |
| **Architecture review** | A review of how your app uses Shiny and the platform underneath it: background execution, permissions, battery, lifecycle, and the OEM quirks that only show up in the field. |
| **Private office hours** | Scheduled time with the maintainer for design questions, code walkthroughs and "is this the right approach?" before it is built. |

Engagements are sized to the project, from a single architecture review to an ongoing agreement.

### Common starting points

- **Shipping background BLE or offline sync** and seeing it behave differently across devices and OS versions.
- **Migrating from Xamarin** (Xamarin.Forms, or a set of Xamarin plugins) to .NET MAUI and Shiny.
- **Modernizing .NET Framework** applications onto modern .NET, including the services behind your mobile apps.
- **A production incident** that needs someone who knows the library internals.

## Where should I post?

Match what you have on the left to where it goes on the right.

| What you have | Where it goes |
| :--- | :--- |
| Something crashes, or behaves differently than the docs say | **An issue** in that library's repo — [find it below](#file-an-issue-in-the-right-repo) |
| "How do I…?", "Which library should I use?", "Is this the right approach?" | [**Discussions**](https://github.com/orgs/shinyorg/discussions) |
| A quick sanity check, or you'd rather just talk it through | [**Discord**](https://mauiverse.net/discord/) |
| A feature idea that isn't fully formed yet | [**Discussions**](https://github.com/orgs/shinyorg/discussions) first — open an issue once it firms up |
| A feature request you can describe concretely | **An issue** in the repo that would implement it |
| Something wrong, missing, or unclear in these docs | [**An issue or PR** on `shinyorg/documentation`](https://github.com/shinyorg/documentation/issues/new) |
| A security issue | **Do not** open a public issue — see [Security](#security) below |
| Shipping to production and want priority help, an SLA or an architecture review | [**Commercial support**](#commercial-support) |
| Private, commercial, or contractual questions | [**ShinySoft Technologies**](https://shinysoft.biz) |
| You want to keep this maintained | [**Sponsor**](https://sponsor.shinylib.net) |

:::tip[Not sure whether it's a bug?]
Post it in [Discussions](https://github.com/orgs/shinyorg/discussions). Sorting
that out is exactly what the forum is for, and it saves you writing a bug
report for something that turns out to be a one-line fix in your own code.
:::

### What makes a report actionable

Most reports that stall do so for the same handful of reasons. Include:

- **Package name and version** — `Shiny.BluetoothLE 4.1.0`, not "the latest".
- **Platform and OS version** — iOS 18.2, Android 15, and whether it's a
  simulator/emulator or a physical device. Several of these libraries wrap
  platform APIs that genuinely differ between the two.
- **The .NET / MAUI version** and your target framework.
- **What you expected and what happened**, with the full exception and stack
  trace if there is one.
- **A repro.** A small failing project is worth more than any description. If
  you can reproduce it against one of the
  [samples](/foundation/apps/), say which one and what you changed.

## Security

Please don't report security vulnerabilities in a public issue or on Discord.
Use GitHub's private advisory flow on the affected repository
(**Security → Report a vulnerability**), which reaches the maintainers without
disclosing the problem first.

## Contributing

Fixes and improvements are welcome across every repo. If the change is
substantial, open a [Discussion](https://github.com/orgs/shinyorg/discussions)
or an issue before you write it — it's the cheapest way to find out whether the
approach fits before you spend the evening on it.

Building something with Shiny? It can be listed on
[Apps & Samples](/foundation/apps/).
