Shiny.AspNet is a set of independent libraries for ASP.NET Core. Each one is a single package you
add to an existing app, registered the ASP.NET way — `builder.Services.Add…()`, `app.Map…()` or
`app.Use…()` — and every `Map…` returns an `IEndpointConventionBuilder`, so `RequireAuthorization`,
`RequireCors`, `RequireRateLimiting` and the rest of ASP.NET's own conventions apply to everything a
library maps.

They are ports of the [Shiny HTTP Server](/httpserver/) add-ons, re-hosted on Kestrel. All of them are
trim and Native AOT clean.

## Coming from Shiny HTTP Server

The protocol code, stores and options are the same; what changes is how a library attaches to the
server:

- `server.MapX(...)` becomes `app.MapX(...)` on any `IEndpointRouteBuilder`, including route groups,
  and returns an ASP.NET convention builder. The httpserver-only wrappers (`RequireIpFilter`,
  `AllowAnyIp`) are gone — use ASP.NET's middleware for those.
- Request handlers take `Microsoft.AspNetCore.Http.HttpContext`; store and hook delegates keep their
  shapes.
- Anything that followed the `HttpServer` lifecycle follows the ASP.NET host instead — tunnels,
  discovery and certificate renewal start once Kestrel is listening.
