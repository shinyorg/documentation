## 1.0 TBD
<RN type="feature">
**Initial release** — `Shiny.Mobile.LiveActivities` puts iOS Live Activities (ActivityKit) and Android 16
Live Updates behind one API: `ILiveActivityManager` (`Start`/`Update`/`End`/`EndAll`/`GetAll`), a typed
`LiveActivityContent` (title, body, short status, progress, stale date, free-form data), and
`ILiveActivityDelegate` for lifecycle + push token callbacks. Unsupported platforms report
`IsSupported == false` and no-op, so shared view models need no platform branching.
</RN>
<RN type="feature">
**iOS via an ActivityKit Swift shim** — ActivityKit is Swift-only, so the package binds a small `@objc`
shim (built from its Xcode project as part of the .NET build). One shared `ShinyActivityAttributes` type
with a fixed content-state schema means apps don't hand-write Swift attributes structs, and a
push-to-start payload always names `"ShinyActivityAttributes"`. Observation starts at app launch, so
activities that outlived the process — or were started by a push — still report their tokens.
</RN>
<RN type="feature">
**A widget extension template** — WidgetKit requires SwiftUI to render a Live Activity, so the repo ships
a data-driven widget (Lock Screen + Dynamic Island) that renders whatever content you send. Add it in
three steps, then reference it with an `<XcodeProject Kind="AppExtension">` item. Its Swift is
compile-checked in CI.
</RN>
<RN type="feature" platform="Android">
**Android 16 Live Updates** — `Notification.ProgressStyle` plus promoted-ongoing and short critical text,
giving the status bar chip and always-on display treatment. Android 8–15 degrade to an ongoing progress
notification. Subclass `LiveActivityManager` and override `CreateBuilder` to restyle.
</RN>
<RN type="feature">
**Push token plumbing** — `OnPushToStartTokenChanged` (one per install, iOS 17.2+) and
`OnPushTokenChanged` (one per activity) surface the two ActivityKit tokens, which are distinct from the
device's APNs token. Pair with `Shiny.Extensions.Push` on the server, which tracks them as
`PushTokenKind.LiveActivityStart` / `LiveActivityUpdate`.
</RN>
<RN type="feature">
**`LiveActivityContentSchema`** — the public serializer for the content-state contract shared by the C#
model, the Swift `ContentState`, and a server's `content-state`. Dates encode as seconds since
2001-01-01 to match Swift's default `Codable` `Date` decoding, not the Unix epoch.
</RN>
