## v4

### 4.1.0 - TBD
<RN type="feature">`IMusicPlayer.CreateVuMeter(implied?, interval?)` returns an `IVuMeter` — an event-based VU meter (`LevelChanged` raising `VuLevel { Position, Rms, Peak, Energy }`) for the current playback. It reports `IsLive` so callers can tell a real output tap from the implied approximation. Also adds `AudioLevels.SampleAt(position)` for a single implied reading</RN>
<RN type="feature" platform="Android">The Android VU meter is a **real audio-output tap** via `android.media.audiofx.Visualizer` (`IsLive == true`), attached to a stable audio session id so it survives track changes. Requires the app to hold `RECORD_AUDIO`; without it, `CreateVuMeter` falls back to the implied meter</RN>
<RN type="feature" platform="iOS">The Apple VU meter is the **implied** meter (`IsLive == false`): `VuLevel`s are synthesized from the `AudioLevels` analysis at the current playback position, because `MPMusicPlayerController` plays out of process and exposes no output tap</RN>
<RN type="enhancement" platform="Android">`IMusicPlayer.PlayAsync` now prepares the track **asynchronously** (`MediaPlayer.PrepareAsync`) instead of blocking the caller on the synchronous `Prepare()`. The call returns as soon as playback is initiated — matching the Apple implementation's fire-and-forget behaviour — and transitions to `Playing` from the prepared callback. `Position`/`Duration` report `Zero` and `Seek` is ignored during the brief prepare window. This keeps callers (e.g. an AI `play_track` tool) from blocking until the track has buffered</RN>
<RN type="feature">`AnalyzeLevelsAsync(trackId, window?)` on `IMediaLibrary` — decodes a track to PCM **offline, without playing it**, and returns an `AudioLevels` with per-window `Rms`/`Peak` envelopes (normalized `0.0–1.0`) for drawing a waveform / VU meter, plus `Sections`: contiguous `AudioSection` runs classified by relative `AudioEnergy` (`Silent`/`Quiet`/`Moderate`/`Loud`) — the coarse "song structure" for locating an intro, chorus, or solo. Returns `null` for DRM-protected / streaming-only tracks that cannot be decoded to PCM (the same tracks `CopyTrackAsync` refuses)</RN>
<RN type="feature" platform="Android">Android implements `AnalyzeLevelsAsync` by copying the track to a temp file and decoding it with `MediaExtractor` + `MediaCodec` (16-bit PCM) in the background; the temp copy keeps analysis working while the same track is playing</RN>
<RN type="feature" platform="iOS">Apple platforms implement `AnalyzeLevelsAsync` by exporting the track (`AVAssetExportSession`) and decoding the copy with `AVAssetReader`. Decoding a copy — rather than the `ipod-library` asset the system player holds exclusively during playback — means analysis works **while the track is playing**, not only when stopped. DRM-protected tracks aren't exportable and return `null`</RN>
<RN type="feature">`LyricsExtensions.GetInstrumentalGaps(duration?, minimumGap?)` and `ParseSyncedLyrics()` (namespace `Shiny.Music`) — derive the instrumental (no-vocal) stretches of a track (intro, breaks, solos, outro) from time-synced LRC lyrics alone. Because it needs **no audio decode, it works even for DRM tracks** where `AnalyzeLevelsAsync` returns `null`; combine the two to tell a loud solo from a quiet intro</RN>
<RN type="feature">`Shiny.Music.Extensions.AI` — new `analyze_song_structure` tool in the `AddLibrary()` area returns a track's instrumental gaps and audio-energy sections (in seconds) so an agent can start playback at a specific moment — "play the famous guitar solo". `play_track` now accepts an optional `start_seconds` to begin partway in</RN>

### 4.0.1 - July 24, 2026
<RN type="fix" platform="iOS">`PlayAsync` no longer occasionally fails to start a track on iOS/Mac Catalyst. `MPMusicPlayerController.SetQueue` loads its queue asynchronously, so the immediate `Play()` could land before the queue was ready and silently no-op — most visible when starting a full-length track (a track that was then seeked appeared to work, because setting `CurrentPlaybackTime` incidentally kicks playback awake). Playback is now retried from the queue's `PrepareToPlay` completion, guarded so it never resurrects a track a `Stop()` cancelled or restarts one already playing</RN>
<RN type="fix" platform="iOS">Stopping playback while a duck is active no longer leaves other audio ducked. On Apple, releasing the session with `SetActive(false)` fails with `IsBusy` while app audio is still draining (e.g. a `Stop()` that interrupts playback mid-announcement), which could strand the `AVAudioSession` in `DuckOthers` — so the next track started already quiet. The session now switches to `MixWithOthers` before attempting to deactivate, reliably releasing the duck even when deactivation cannot run yet</RN>

### 4.0 - July 13, 2026
<RN type="feature">`Volume` (get/set, `0.0`–`1.0`) and `VolumeChanged` on `IMusicPlayer` control and observe the **device-wide system media volume**, independent of any active duck. Reading works on all platforms; observe changes from the hardware buttons, Control Center, or a successful set via `VolumeChanged`</RN>
<RN type="feature">`IsVolumeControlSupported` on `IMusicPlayer` — reports whether the `Volume` setter is honored: `true` on Android, `false` on Apple. Guard writes with it, since setting volume on Apple throws `NotSupportedException`</RN>
<RN type="feature" platform="Android">Android reads and writes the system `STREAM_MUSIC` volume via `AudioManager` (`IsVolumeControlSupported` is `true`); `VolumeChanged` observes the system volume through a `ContentObserver`. The stream is integer-stepped, so a set value is quantized to the nearest step</RN>
<RN type="feature" platform="iOS">Apple reads `AVAudioSession.OutputVolume` reliably, but **setting the volume is not supported** — the setter throws `NotSupportedException` (`IsVolumeControlSupported` is `false`), as iOS/Mac Catalyst expose no supported API to change system volume. `VolumeChanged` fires from KVO on the session's output volume; direct the user to the hardware buttons or an `MPVolumeView` to change volume</RN>
<RN type="fix">Ducking now enforces a **single active duck** — calling `Duck()` while a duck is already active returns a no-op scope instead of superseding the existing one (previously last-writer-wins). This prevents a superseded duck's restore-fade from racing the new duck on the shared volume, which could leave the music stuck at a lowered level; the active duck restores normally when its scope is disposed</RN>
<RN type="feature" breaking platform="Android">Android permission checks now run on **Shiny.Core**'s `AndroidPlatform` (`GetCurrentPermissionStatus` / `RequestAccess`), replacing the built-in activity provider. Your app must be under Shiny hosting — call `.UseShiny()` in MAUI (or use `ShinyAndroidApplication` + `ShinyAndroidActivity` natively) — otherwise `IMediaLibrary` cannot resolve `AndroidPlatform`. This makes `Shiny.Core` a dependency on the Android target and fixes the config-change-during-dialog hang from the previous fragment-based implementation</RN>
<RN type="feature" platform="iOS">`SearchCatalogAsync(term, limit)` on `IMediaLibrary` — searches the Apple Music streaming **catalog** (via MusicKit `MusicCatalogSearchRequest`), returning tracks that need not be in the user's library; the first call prompts for MusicKit authorization and results come back empty without a subscription/authorization rather than throwing</RN>
<RN type="feature" platform="iOS">`CatalogId` property on `MusicMetadata` — set on catalog search results; passing such a track to `IMusicPlayer.PlayAsync` streams it by catalog id via `MPMusicPlayerStoreQueueDescriptor`, so catalog tracks are playable without adding them to the library (active Apple Music subscription required). `SearchCatalogAsync` is Apple-only and throws `PlatformNotSupportedException` on Android</RN>
<RN type="feature" platform="iOS">`Shiny.Music.Extensions.AI` — new opt-in `AddCatalog()` area exposing a `search_catalog` tool so an LLM agent can search the Apple Music streaming catalog and play results via `play_track`; Apple-only and deliberately excluded from `AddAll()`, so guard the registration with `#if IOS || MACCATALYST`</RN>

### 3.2 - July 7, 2026
<RN type="feature">`Shiny.Music.Extensions.AI` — a new companion package that exposes the music library and player as [Microsoft.Extensions.AI](https://learn.microsoft.com/dotnet/ai/) tool functions, so an LLM chat agent can search, browse, play, and manage playlists through natural language; register with `AddMusicAITools(...)` and pass the resolved `MusicAITools.Tools` to any `IChatClient`</RN>

### 3.1 - July 7, 2026
<RN type="feature">Audio ducking — `Duck(DuckOptions?)` on `IMusicPlayer` lowers the currently playing music so an announcement can be heard over top, returning an `IAsyncDisposable` scope that restores full volume when disposed; ideal for TTS prompts and navigation callouts</RN>
<RN type="feature">`DuckOptions` record — control the ducked `Level` (0.0-1.0) plus `FadeIn`/`FadeOut` ramp durations; defaults to 20% with 200ms fades</RN>
<RN type="feature">`IsDucked` property on `IMusicPlayer` — reports whether a duck scope is currently active</RN>
<RN type="enhancement">Last-writer-wins duck semantics — a newer duck supersedes an older one; disposing the active scope restores volume while disposing a superseded scope is a no-op, and ducking with nothing playing returns a no-op scope</RN>
<RN type="feature" platform="Android">Android ducking lowers the player's own track, honoring `DuckOptions.Level` and the fade durations exactly</RN>
<RN type="feature" platform="iOS">Apple ducking activates `AVAudioSession` with `DuckOthers` (level and fades are advisory — the OS controls duck depth and ramp); announcement audio played through the app audio session plays at full volume over the ducked music</RN>
<RN type="feature">`GetTrackByIdAsync(trackId)` on `IMediaLibrary` — resolve a single track by its identifier, returns `null` if not found</RN>
<RN type="feature">`GetTracksByIdsAsync(trackIds)` on `IMediaLibrary` — resolve multiple tracks in a single query, ordered to match the input; ideal for rehydrating a saved queue or favorites list</RN>
<RN type="feature">`GetPlaylistByIdAsync(playlistId)` on `IMediaLibrary` — resolve a single playlist (with song count) by identifier, including custom playlists; returns `null` if not found</RN>
