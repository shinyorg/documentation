`Shiny.UniversalHubs.Multipeer` serves and joins hubs over Apple's **MultipeerConnectivity**. It picks the radio
itself: the Wi-Fi network when both devices are on one, peer-to-peer Wi-Fi (AWDL) when they aren't, and Bluetooth when
Wi-Fi is off. Two iPhones on a plane get Wi-Fi bandwidth instead of BLE's, and no MTU.

It only connects Apple devices: iPhone, iPad, Mac Catalyst and macOS. Android players use another transport against the
same host, in the same hub, with the same groups and pushes.

## Setup

```bash
dotnet add package Shiny.UniversalHubs.Multipeer
```

```csharp
// host - one Multipeer service type per server, then each hub opts in
builder.Services.AddUniversalServer(server => server
    .Multipeer("mygame-mc", o => o.DisplayName = "Allan's iPad")
    .AddHub<GameHub>("game", hub => hub.UseMultipeer().UseHttp("_mygame._tcp")));

// client
builder.Services.AddUniversalHubClient<IGameHub>("game", o => o
    .UseHttp("_mygame._tcp")
    .UseMultipeer("mygame-mc", mc => mc.InviteTimeout = TimeSpan.FromSeconds(10)));
```

Register it in shared code. Where MultipeerConnectivity doesn't exist (Android, Windows, Linux) it reports itself
unsupported and is skipped.

### Info.plist

Both the host and the client need the Multipeer service type in `NSBonjourServices`, as `_tcp` **and** `_udp`, and a
local network usage description. Without them iOS finds nothing and says nothing. The library logs a warning at start
when either is missing.

```xml
<key>NSLocalNetworkUsageDescription</key>
<string>The local network is used to talk to nearby devices</string>
<key>NSBonjourServices</key>
<array>
    <string>_mygame._tcp</string>       <!-- the hub's HTTP mDNS type, if it has one -->
    <string>_mygame-mc._tcp</string>    <!-- Multipeer -->
    <string>_mygame-mc._udp</string>
</array>
```

### The service type

- 1 to 15 lowercase letters, digits and hyphens, with at least one letter and no leading, trailing or doubled hyphen.
- It **must differ** from the name inside any hub's mDNS service type (`mygame` for `_mygame._tcp`):
  MultipeerConnectivity advertises over Bonjour as `_{type}._tcp` too.
- One per server. Every running hub served over Multipeer is listed in its one advertisement.

### Options

| Host (`MultipeerHostOptions`) | Default | |
|---|---|---|
| `DisplayName` | the server's `LocalName` | The host's Multipeer name. At most 63 UTF-8 bytes; longer is cut |

| Client (`MultipeerClientOptions`) | Default | |
|---|---|---|
| `DisplayName` | `Hub client` | This device's Multipeer name, which the host sees as `connection.MultipeerPeer().DisplayName`. The hub client name still travels in the handshake |
| `InviteTimeout` | 10 seconds | How long the host gets to accept and connect before the next transport is tried |

## In the Hub

```csharp
public override Task OnConnectedAsync(HubConnection connection)
{
    // connection.Id: mc:{id}
    if (connection.Transport is MultipeerHostTransport)
        Log(connection.MultipeerPeer()?.DisplayName);   // the peer's radio name
    return Task.CompletedTask;
}
```

## Discovery and Connecting

- `DiscoverAll()` merges Multipeer hosts with the other transports by name. `host.IsSeenOver<MultipeerClientTransport>()`
  says whether it is seen over Multipeer.
- The advertisement lists the running hubs, so a client only sees hosts running its hub.
- `Connect` tries it in the client's priority order. `new HubConnectOptions("Allan").Only<MultipeerClientTransport>()`
  uses nothing else.

## What's Different

- **One session per hub connection.** The host accepts each client into its own encrypted `MCSession`, so
  MultipeerConnectivity's 8-peer limit never applies and clients never connect to each other.
- **Files** move as Multipeer resources. **Media channels** ride the session as reliable, ordered messages. **Renames
  work.**
- **Resume.** A Multipeer session ends when the app goes to the background or the peer goes out of range. The client
  invites the host again and [resumes](/universalhubs/client/#resume) as the same connection within the host's resume
  window.
- **The host's peer id** is kept across launches, so a relaunched host isn't listed twice.

See [How It Works](/universalhubs/how-it-works/#multipeer) for the wire protocol.
