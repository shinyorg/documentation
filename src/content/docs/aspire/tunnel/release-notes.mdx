### 1.1.0 - TBD
<RN type="feature" repo="aspire">Tunnel resources whose public URL is their connection string, so `WithReference` and `WithTunnelUrl` resolve it and wait for the tunnel to open</RN>
<RN type="feature" repo="aspire">Pluggable providers via `AddTunnel`, taking any `Shiny.Net.HttpServer` `ITunnelProvider`</RN>
<RN type="feature" repo="aspire">Zero-account quick tunnels via `WithQuickTunnel` — pinggy, sish, Serveo and localhost.run</RN>
<RN type="feature" repo="aspire">SSH remote forwarding via `WithSshTunnel`, with host-key pinning, ephemeral keys and automatic reconnect</RN>
<RN type="feature" repo="aspire">The Shiny relay hosted in the app model via `AddShinyRelay`, so embedded servers and MAUI apps can register into a development environment</RN>
<RN type="feature" repo="aspire">Azure Relay Hybrid Connections via `WithAzureRelayTunnel`, with `ParameterResource` support for the connection string</RN>
<RN type="feature" repo="aspire">`cloudflared` as a container resource via `WithCloudflareTunnel`, including named tunnels on your own domain</RN>
<RN type="feature" repo="aspire">The ngrok agent as a container resource via `WithNgrokTunnel`, including reserved domains</RN>
<RN type="feature" repo="aspire">SSH local forwarding via `AddSshPortForward`, exposing a service behind a bastion as an ordinary connection string</RN>
<RN type="feature" repo="aspire">Tunnels open on endpoint allocation rather than readiness, so a resource may reference its own public URL</RN>
