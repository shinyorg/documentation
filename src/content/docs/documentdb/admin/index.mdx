**ShinyDocDbMyAdmin** is a phpMyAdmin-style front end for DocumentDb stores. Connect to a database,
browse the documents in it, edit them, run SQL, manage JSON indexes, and move data in and out. No user
management, no server administration — just the documents.

It comes in two forms over one admin layer: a **web app**, shipped as a container image, and a
**[terminal app](/documentdb/admin/terminal/)**, shipped as a `dotnet tool`. They share the connection
store, the secret handling and the bundle format, so they are the same tool with two ways to look at it.

:::tip[Try it without installing anything]
A public instance runs the `:demo` image against a read-only sample store — **[try the live
sample](https://docdbmyadmin.acrhome.ca/)**. See [Demo mode](/documentdb/admin/demo-mode/) for what is
switched off there.
:::

The web app is Blazor Server, shipped as a **container image and nothing else**:

```bash
docker run -p 8085:8080 -v shiny-docdb-myadmin:/data ghcr.io/shinyorg/shiny-docdb-myadmin
```

The terminal app is where a local install makes sense:

```bash
dotnet tool install -g ShinyDocDbMyAdmin.Tui
shinydocdb
```

:::note[Why is the web app not a tool as well?]
A `dotnet tool` form of the Blazor app came out at ~120 MB — almost entirely native provider binaries for
every RID it might run on — to deliver what one image delivers for the platform you are actually on. The
terminal front end is the installable shape, and it is the one you would want installed anyway: it is what
you reach for when you are already in a terminal.
:::

## What's in it

| Page | What it's for |
|---|---|
| [Connections](/documentdb/admin/connections/) | Point the tool at a database — a server, an uploaded file, or one your host declares. |
| [Browse & edit](/documentdb/admin/browse/) | A sampled-column grid with JSON-path filters, a formatted JSON view, and a JSON editor. |
| [Structure & indexes](/documentdb/admin/structure/) | The inferred shape of a type, table statistics, and one-click index management. |
| [Query console](/documentdb/admin/query-console/) | DocumentDb's string query grammar and the database's own SQL, with query plans. |
| [History](/documentdb/admin/history/) | Temporal versions, field-level diffs and restore. |
| [Geometry](/documentdb/admin/geometry/) | GeoJSON drawn on a server-rendered map, with per-feature statistics. |
| [Full text](/documentdb/admin/full-text/) | Ranked search through the provider's own full-text engine. |
| [Vectors](/documentdb/admin/vectors/) | Embedding statistics, sidecar drift detection, and exact nearest-neighbour search. |
| [Blobs](/documentdb/admin/blobs/) | Attached payloads, listed and previewed without ever selecting the bytes. |
| [Generate test data](/documentdb/admin/generate/) | More documents that look like the ones already there. |
| [Import & export](/documentdb/admin/import-export/) | Streaming JSON, NDJSON, CSV and envelope JSON in both directions. |
| [AI assistant](/documentdb/admin/assistant/) | A read-only chat over your data, configured per connection. |
| [Aspire AppHost](/documentdb/admin/aspire/) | The tool as an Aspire resource, wired to the stores you already model. |
| [Terminal UI](/documentdb/admin/terminal/) | The same tool as a `dotnet tool`, sharing this one's connections and bundles. |
| [Configuration & security](/documentdb/admin/configuration/) | Settings, the secret key, read-only mode, and what is defended against. |
| [Demo mode](/documentdb/admin/demo-mode/) | One flag that turns the whole app into a public playground. |

## Supported providers

Every **relational** DocumentDb backend:

| Provider | Connection | Notes |
|---|---|---|
| SQLite | file, uploadable | |
| SQLCipher | file, uploadable | needs the encryption key |
| DuckDB | file, uploadable | takes an exclusive lock while open |
| PostgreSQL | server | |
| SQL Server | server | |
| MySQL | server | |
| MariaDB | server | |
| Oracle 23ai+ | server | |
| CockroachDB | server | |

The document stores (MongoDB, Cosmos DB, LiteDB, IndexedDB, …) are deliberately out of scope: this tool
works against the shared `Id / TypeName / Data / CreatedAt / UpdatedAt` envelope over ADO.NET, which only
the relational providers expose.

## Explorer

Connection → table → `TypeName`, with live document counts. Tables are classified by probing for the
envelope, so temporal/blob/spatial sidecars are recognised and kept out of the way rather than shown as
if they were yours to edit.

## Create

A documents table (using the provider's own DDL) and a type (by writing its first document), so a database
whose store has never run isn't a dead end.

## Running it

Two published tags, one build. `:latest` is the ordinary tool; `:demo` is the same image with
[demo mode](/documentdb/admin/demo-mode/) already on, for a public playground. Pin `:<version>` or
`:demo-<version>` when you want them to hold still.

The volume holds saved connections, saved queries and uploaded database files; drop it and the UI starts
empty every time.

```bash
docker run -p 8085:8080 -v shiny-docdb-myadmin:/data ghcr.io/shinyorg/shiny-docdb-myadmin
```

To reach a database *file* on your machine, mount its directory and use the container's path in the
connection string:

```bash
docker run -p 8085:8080 -v shiny-docdb-myadmin:/data \
  -v /Users/me/databases:/databases:ro \
  ghcr.io/shinyorg/shiny-docdb-myadmin
```

From a clone of the repo, either build the image or just run the project:

```bash
docker build -f src/ShinyDocDbMyAdmin/Dockerfile -t shiny-docdb-myadmin .
dotnet run --project src/ShinyDocDbMyAdmin
```

In an Aspire AppHost it models as a resource — see [Aspire AppHost](/documentdb/admin/aspire/).
