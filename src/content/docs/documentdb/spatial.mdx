---
title: Spatial / Geo Queries
---

Spatial queries let you find documents by geographic proximity — within a radius, inside a bounding box, nearest to a point — or by full-geometry topological relationships (intersects, contains, overlaps, …). Supported on **SQLite**, **PostgreSQL**, **MySQL**, **SQL Server**, **Oracle**, and **DuckDB** (bbox prune + in-process relate/refine — no native spatial extension needed), plus **CosmosDB** (native GeoJSON) and **MongoDB** (`2dsphere`). The fallback stores (LiteDB, IndexedDB, Azure Table, DynamoDB) throw `NotSupportedException`.

## Spatial Types

### GeoPoint

A geographic coordinate using WGS84. Serializes as GeoJSON `{"type":"Point","coordinates":[longitude,latitude]}`.

```csharp
public readonly record struct GeoPoint(double Latitude, double Longitude);
```

### GeoBoundingBox

A rectangular area for bounding box queries.

```csharp
public readonly record struct GeoBoundingBox(
    double MinLatitude, double MinLongitude,
    double MaxLatitude, double MaxLongitude);
```

### SpatialResult\<T\>

Wraps a document with its computed distance from the query center point.

```csharp
public class SpatialResult<T> where T : class
{
    public required T Document { get; init; }
    public double DistanceMeters { get; init; }
}
```

## Configuration

Register which `GeoPoint` property to use for spatial indexing per document type using `MapSpatialProperty`:

```csharp
public class Restaurant
{
    public string Id { get; set; } = "";
    public string Name { get; set; } = "";
    public GeoPoint Location { get; set; }
    public string Cuisine { get; set; } = "";
}

var store = new DocumentStore(new DocumentStoreOptions
{
    DatabaseProvider = new SqliteDatabaseProvider("Data Source=mydata.db")
}
.MapSpatialProperty<Restaurant>(r => r.Location)
);
```

:::tip[AOT-safe overload]
For full AOT/trimming safety, use the delegate overload which avoids expression compilation:
```csharp
.MapSpatialProperty<Restaurant>("Location", r => r.Location)
```
:::

You can map multiple types:

```csharp
var options = new DocumentStoreOptions
{
    DatabaseProvider = new SqliteDatabaseProvider("Data Source=mydata.db")
}
.MapSpatialProperty<Restaurant>(r => r.Location)
.MapSpatialProperty<Hotel>(h => h.Coordinates);
```

### Optional (nullable) locations

The mapped property may be a nullable `GeoPoint?` — map it the same way, and a document whose location
is `null` is simply left out of the spatial index (it still stores and queries normally otherwise). This
is the common case for records where coordinates are optional, e.g. a calendar event that may or may not
have a place attached:

```csharp
public class CalendarEvent
{
    public string Id { get; set; } = "";
    public string Title { get; set; } = "";
    public GeoPoint? Location { get; set; }   // optional
}

options.MapSpatialProperty<CalendarEvent>(e => e.Location);
```

Inserting or updating an event with a `null` location does **not** throw and does **not** index it; those
documents never appear in `WithinRadius`/`WithinBoundingBox`/`NearestNeighbors` results. Clearing a
previously-set location on update (setting it back to `null`) purges the stale index entry, so subsequent
spatial queries no longer match it.

## Checking Provider Support

Not all providers support spatial queries. Check at runtime:

```csharp
if (store.SupportsSpatial)
{
    var nearby = await store.WithinRadius<Restaurant>(center, 5000);
}
```

| Provider | `SupportsSpatial` |
|---|---|
| SQLite | `true` (when spatial properties are mapped) |
| SQLCipher | `true` (inherits SQLite R*Tree support) |
| CosmosDB | `true` (when spatial properties are mapped) |
| LiteDB | `false` |
| MySQL | `false` |
| SQL Server | `false` |
| PostgreSQL | `false` |

## Queries

### WithinRadius

Find documents within a distance (meters) of a center point, ordered by distance ascending. Returns `SpatialResult<T>` with the computed distance.

```csharp
var nearby = await store.WithinRadius<Restaurant>(
    new GeoPoint(45.5231, -122.6765), // Portland, OR
    5000); // 5km radius

foreach (var result in nearby)
{
    Console.WriteLine($"{result.Document.Name} — {result.DistanceMeters:N0}m away");
}
```

With an additional predicate filter:

```csharp
var italianNearby = await store.WithinRadius<Restaurant>(
    new GeoPoint(45.5231, -122.6765),
    5000,
    filter: r => r.Cuisine == "Italian");
```

### WithinBoundingBox

Find documents within a rectangular geographic area.

```csharp
var inArea = await store.WithinBoundingBox<Restaurant>(
    new GeoBoundingBox(45.0, -123.0, 46.0, -122.0));
```

With a filter:

```csharp
var inArea = await store.WithinBoundingBox<Restaurant>(
    new GeoBoundingBox(45.0, -123.0, 46.0, -122.0),
    filter: r => r.Cuisine == "Italian");
```

### NearestNeighbors

Find the K closest documents to a point, ordered by distance ascending.

```csharp
var closest = await store.NearestNeighbors<Restaurant>(
    new GeoPoint(45.5231, -122.6765),
    count: 10);

foreach (var result in closest)
{
    Console.WriteLine($"{result.Document.Name} — {result.DistanceMeters:N0}m");
}
```

With a filter:

```csharp
var closestItalian = await store.NearestNeighbors<Restaurant>(
    new GeoPoint(45.5231, -122.6765),
    count: 5,
    filter: r => r.Cuisine == "Italian");
```

## Full geometry (lines, polygons & predicates)

Beyond points, you can map full **OGC geometry** and run topological predicate queries. The geometry model
lives in `Shiny.DocumentDb` and serializes as GeoJSON in the document body:

| Type | Notes |
|---|---|
| `GeoPoint` | the existing point struct; implicitly converts to a point geometry |
| `GeoLineString` | 2+ coordinates |
| `GeoPolygon` | exterior ring (4+, closed) + optional holes |
| `GeoMultiPoint` / `GeoMultiLineString` / `GeoMultiPolygon` | homogeneous collections |
| `GeoGeometryCollection` | heterogeneous collection |

Map a geometry property just like a point:

```csharp
opts.MapSpatialProperty<Zone>(z => z.Area);   // Area is a Geometry? property
```

### Predicate queries

Every predicate reads *stored-geometry &lt;predicate&gt; query-geometry*, takes an optional
`orderByDistanceFrom` (a point **or** geometry — results are ordered by ascending distance and
`SpatialResult.DistanceMeters` is populated), an optional `filter` that pushes down to the database, and
returns `SpatialResult<T>`:

```csharp
// "which zones contain this GPS point?" — a bare point works via implicit conversion
var here = await store.GeoIntersects<Zone>(new GeoPoint(45.52, -122.68));

// zones fully inside a query polygon, nearest-first
var inside = await store.GeoContainedBy<Zone>(searchArea, orderByDistanceFrom: new GeoPoint(45.5, -122.6));

// everything within 500 m of a route line
var near = await store.GeoWithinDistance<Zone>(route, meters: 500);
```

Available: `GeoIntersects`, `GeoContainedBy`, `GeoContains`, `GeoDisjoint`, `GeoTouches`, `GeoCrosses`,
`GeoOverlaps`, `GeoEquals`, `GeoCovers`, `GeoCoveredBy`, and `GeoWithinDistance(geometry, meters)`.
`NearestNeighbors` also works over geometry-mapped types (point-to-geometry distance).

### Measurement & validity

`Geometry` exposes in-memory `Area` (m²), `Length`/`Perimeter` (m), `Centroid`, `NumPoints`,
`NumGeometries`, plus `IsValid`, `IsSimple`, and a lightweight `MakeValid()`. Because these are ordinary
properties, you can index measurement with a materialized computed property and filter on it server-side:

```csharp
opts.MapComputedProperty<Zone>(z => z.Area!.Area, indexed: true);   // then: Query(z => z.Area!.Area > 1e6)
```

### Provider tiers

| Provider | Geometry predicates |
|---|---|
| **SQLite** | R\*Tree bbox prune + in-process relate/refine (dependency-free) |
| **PostgreSQL / MySQL / SQL Server / Oracle / DuckDB** | dependency-free **envelope-sidecar** table (four indexed columns) + in-process relate/refine — no PostGIS/`geography`/`SDO_GEOMETRY`/`spatial` extension |
| **CosmosDB** | native `ST_INTERSECTS`/`ST_WITHIN`/`ST_DISTANCE`; finer predicates refine over the intersect candidate set |
| **MongoDB** | `2dsphere` + native `$geoIntersects`/`$geoWithin`/`$near`; finer predicates & non-point distance refine in-process |
| LiteDB / IndexedDB / Azure Table / DynamoDB | `SupportsSpatial => false` |

On the relational engines the pass-1 prune uses a plain B-tree over the envelope columns (weaker than a true
2-D spatial index for wide longitude spans, but still index-assisted — not a full scan). A native
`ST_*`/`SDO` pushdown tier could be layered on later per engine.

`GeoDisjoint` is anti-selective (the answer is mostly rows *outside* any bbox), so it scans the type — O(n)
on the two-pass providers. Distances on the two-pass/refine paths are a Haversine/planar approximation;
native `ST_DISTANCE` is geodesic, so ordering can differ on near-ties across providers.

## How It Works

### SQLite — R*Tree Sidecar

SQLite uses [R*Tree virtual tables](https://www.sqlite.org/rtree.html) for spatial indexing. For each table with spatial-mapped types, the library creates two companion tables:

- **`{table}_spatial_map`** — maps document text IDs to integer rowids (R*Tree requires integer keys)
- **`{table}_spatial`** — the R*Tree index storing latitude/longitude bounding boxes

These tables are created automatically when the table is first used. CRUD operations automatically sync the spatial index:

| Operation | Spatial Sync |
|---|---|
| Insert / Update / Upsert | Extracts `GeoPoint` from document and upserts into R*Tree |
| Remove | Deletes spatial entry for that document |
| Clear | Removes all spatial entries for that type |

**Radius queries** use a two-phase approach: the R*Tree provides a fast bounding box pre-filter, then a Haversine post-filter computes exact distances for precision.

**Nearest neighbor queries** use an expanding bounding box strategy — starting at 10km and doubling until enough candidates are found.

### CosmosDB — Native GeoJSON

CosmosDB has built-in geospatial support. The `GeoPoint` type serializes as GeoJSON directly in the document:

```json
{
  "id": "rest-1",
  "typeName": "Restaurant",
  "data": {
    "name": "Pizzeria Roma",
    "location": {
      "type": "Point",
      "coordinates": [-122.6765, 45.5231]
    }
  }
}
```

CosmosDB automatically indexes GeoJSON properties. The library adds spatial index policies to the container during initialization. Queries use native SQL functions:

- **WithinRadius**: `ST_DISTANCE(c.data.location, point) <= @radius`
- **WithinBoundingBox**: `ST_WITHIN(c.data.location, polygon)`
- **NearestNeighbors**: `ORDER BY ST_DISTANCE(c.data.location, point) OFFSET 0 LIMIT @count`

No sidecar tables or manual sync needed — CosmosDB handles everything natively.
