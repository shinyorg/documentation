The **Design** tab, and the **Slide Master** view that edits what every slide inherits.

## Themes and variants

Seven built-in themes (`SlideThemeDefinition.BuiltIn`), each with colour **variants**. Applying one
rewrites the theme part's colour scheme and major/minor fonts, so every placeholder and theme-coloured
shape in the deck follows — in PowerPoint too.

```csharp
var c = editor.Controller!;

c.ApplyTheme(SlideThemeDefinition.BuiltIn[2]);
c.ApplyColorVariant(variant);
```

Where a theme names a font the platform does not have, a similar face is substituted — ending on the
bundled Carlito or Caladea, so a browser (which has no system fonts) still sets the theme in a
proportional face of the right kind rather than the monospace fallback.

A slide with no background written anywhere paints the theme's first background colour (`bg1`), as
PowerPoint does — which is what makes a dark theme's slides dark.

## Slide size

**16:9**, **4:3** or custom. The content scales with the slide.

```csharp
c.SetSlideSize(1280, 720);   // 16:9; 960 x 720 is 4:3
```

## Format background

Solid, gradient or picture, for **this slide** or **all** slides; **Reset** goes back to what the layout
and master give.

```csharp
c.SetBackground(background, applyToAll: false);   // a SlideBackgroundSpec
c.ResetBackground();
```

## Slide Master

View ▸ **Slide Master** opens the master and its layouts, with a contextual **Slide Master** tab. Edit the
text styles and backgrounds there and they are saved back to the master and layout parts, so every slide
using them changes.

```csharp
c.ViewMode = SlideEditorViewMode.SlideMaster;
c.Master;   // the master being edited
```

## Dark mode

The app's light/dark theme reaches only the editor's **surround** and chrome; the slides show the deck's
own theme. `Theme` pins the editor light or dark regardless of the app.
