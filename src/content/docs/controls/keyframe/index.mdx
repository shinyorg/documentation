Declarative animation for .NET MAUI and Blazor. It starts from the CSS `@keyframes` model expressed in XAML (or Razor), and adds a fluent C# timeline API, storyboards, trigger actions, **animated visual-state transitions**, **implicit property transitions**, **item transitions**, Keyframe-driven **page transitions**, a drawn scene graph and a headless frame exporter.

MAUI's own `Animation` class can't **seek**. Everything here is built around one design constraint: evaluating an animation is a **pure function of time**, and nothing reads the previous frame. That is what makes scrubbing, mid-flight reversal, byte-identical export and non-flaky timing tests possible.

Keyframe also does something MAUI's own animations can't: it **animates without taking the property over**. Animations write through an [animation layer](/controls/keyframe/animation-layer/), so the binding, style, visual state or trigger underneath keeps working, and the property shows its own value again when the animation ends.

:::tip[Covers every phase of the MAUI animation spec, today]
The .NET MAUI team's proposal for animations and transitions ([dotnet/maui#40382](https://github.com/dotnet/maui/issues/40382)) is planned in six phases. Each one is available in Shiny now, on both hosts. See [the comparison](#and-the-maui-spec).
:::

## Features

| Feature | Description |
| --- | --- |
| **CSS `@keyframes` semantics in XAML** | `Duration`, `Delay`, `Iterations`, `Direction`, `Fill`, and per-key easing behave the way the web spec says they do, including `Fill="Both"` and `Direction="Alternate"`. |
| **Seekable, reversible playback** | `SeekProgress(0.35)` scrubs, `Rate = -1` reverses from wherever the animation currently sits. No rebuilding, no restart. |
| **CSS easing function syntax** | `cubic-bezier(0.34, 1.56, 0.64, 1)`, `steps(8)`, and `spring(0.35, 14)` parse from a plain string, so a curve copied out of a design tool or browser devtools pastes in verbatim. 38 named curves too. |
| **Implicit keyframes** | omit `Value` on a key and it resolves to the target's live value when playback starts, so a re-triggered animation continues from where it is instead of snapping. |
| **Oklab colour blending by default** | sRGB interpolation dips through grey at the midpoint; Oklab doesn't. `ColorInterpolator.Srgb` and `.LinearRgb` remain available. |
| **Shortest-arc angles** | `Rotation` from 350° to 10° turns forward 20°, not back 340°. `Spin` is there for when multiple turns are the point. |
| **Fluent C# timelines and storyboards** | `TimelineBuilder` composes tracks; `Storyboard` sequences, overlaps and staggers whole timelines on a shared clock, and nests. |
| **A drawn scene graph** | `KeyframeScene` + `KeyframeView` run the same timing model against layers on a canvas (the Lottie-shaped lane) rather than views in the visual tree. |
| **Deterministic offscreen export** | sample a scene at exact frame times, lazily, and encode to GIF with no external dependency. |
| **AOT and trim safe** | the property registry is hand-registered delegates, not reflection and not compiled `Expression` trees, both of which work in the emulator and break on device under Native AOT. |
| **Weak targets** | an infinite animation on a popped page goes inert and is collected, rather than pinning the visual tree. |
| **An animation layer** | animations show a value without owning the property, so bindings, styles and visual states keep working, and `FadeToAsync` running at the same time is handled predictably. |
| **Storyboards in XAML** | `KeyFrame` frames of ordinary `Setter`s reach any bindable property; `Choreography` staggers and sequences, including the staggered list entrance in one element. |
| **Trigger actions** | `BeginAnimation`, `StopAnimation`, `PauseAnimation`, `ResumeAnimation`, `SkipAnimationToEnd`, `SeekAnimation`, used in any trigger's enter and exit actions. |
| **Animated visual states** | `VisualTransition` animates `GoToState` and MAUI's own Pressed, PointerOver, Focused and Disabled states, with most-specific matching, seamless interruption and `StateAnimation`. |
| **Implicit transitions** | `PropertyTransition` animates every change to a property, from any source, like CSS `transition`. |
| **Item transitions** | switch off CollectionView's native item animations, and play staggered appear, add and remove animations. |
| **Reduced motion by default** | everything honours the OS setting; `ReducedMotion="Play"` keeps motion that carries information. |
| **A vsync clock** | `CADisplayLink` (up to 120 Hz), `Choreographer`, `CompositionTarget.Rendering`, separate from MAUI's ticker. |

## And the MAUI spec

The MAUI team's animations and transitions proposal ([dotnet/maui#40382](https://github.com/dotnet/maui/issues/40382)) plans its features as phases. Here is where each one is in Shiny:

| Spec phase | Shiny |
|---|---|
| 1. Animated visual-state transitions (`VisualStateGroup.Transitions`) | [`StateTransitions.Transitions`](/controls/keyframe/transitions/) with `VisualTransition` (`From`, `To`, `Group`, `Duration`, `Easing`, `Delay`, `ReducedMotion`, `Animation`) and `StateAnimation` for `VisualState.Storyboard`. `StateTransitions.GoToState(…, useTransitions)`. |
| 2. Implicit property transitions (`PropertyTransition`) | [`PropertyTransitions.Transitions`](/controls/keyframe/transitions/#implicit-transitions): named, `All`, or any `BindableProperty`. |
| 3. Keyframe storyboards, XAML and C# | `Keyframes` with `Track`/`Key` or spec-style `KeyFrame Cue="60%"` + `Setter`; `Choreography`; `TimelineBuilder`/`Storyboard`; [trigger actions](/controls/keyframe/storyboards/#trigger-actions); `PlayAsync`; `ManualClock` for tests; `IInterpolator<T>` and `ValueBlending` for custom types. **Plus** seek, scrub, live reverse, implicit keys, Oklab colour and shortest-arc rotation. |
| 4. Page, navigation and shared-element transitions | [Page Transitions](/controls/page-transitions/): 14 built-in types, hero flights, tab transitions, per-call navigation overloads, and custom transitions written as Keyframes through `KeyframePageTransition`. |
| 5. Item transitions, including `None` | [`ItemTransitions`](/controls/keyframe/item-transitions/): `Mode="None"`, `Appear`, `Add`, `Remove`, `Stagger`. |
| 6. Native acceleration | A vsync clock on every platform. Compositor offload is not done. |
| Precedence rank that shows without owning | The [animation layer](/controls/keyframe/animation-layer/), using MAUI's existing handler slot. No framework change needed. |
| `Easing.CubicBezier`, `Spring`, `Steps`, `Hold` | `cubic-bezier()`, `spring()`, `bouncy()`, `steps()`, `Hold`, plus 38 named curves, as text or C#. |
| Reduced motion honoured by default | Yes, with `ReducedMotion="Play"` per animation, and seeking is never affected. |
| Per-window vsync clock with platform timestamps | Yes. |
| Blazor | All of the above, on the Web Animations API. |

Where Shiny differs on purpose:
- `PlayAsync` returns `false` when cancelled instead of throwing, so `async void` handlers stay safe.
- The XAML storyboard is called `Choreography`, because the engine's C# `Storyboard` is in the same namespace.
- A `{DynamicResource}` set directly on an animated property is still detached; one set through a style is not.

## Quick Start

An attached property on any `VisualElement`:

```xml
<Border>
    <kf:Animate.Keyframes>
        <kf:Keyframes Duration="0:0:1.2" Iterations="Infinite" Direction="Alternate" Fill="Both">

            <kf:Track Property="Scale">
                <kf:Key Offset="0"   Value="1" />
                <kf:Key Offset="0.5" Value="1.15" Easing="CubicOut" />
                <kf:Key Offset="1"   Value="1" />
            </kf:Track>

            <kf:Track Property="BackgroundColor">
                <kf:Key Offset="0" Value="#2563EB" />
                <kf:Key Offset="1" Value="#EC4899" />
            </kf:Track>

        </kf:Keyframes>
    </kf:Animate.Keyframes>
</Border>
```

The same animation in C#:

```csharp
using Shiny.Controls.Keyframe;
using Shiny.Maui.Controls.Keyframe;

var timeline = TimelineBuilder
    .Create(TimeSpan.FromSeconds(1.2))
    .PingPong()
    .RepeatForever()
    .Fill(FillMode.Both)
    .Animate(box, (v, x) => v.Scale = x, k => k
        .From(1)
        .Key(0.5, 1.15, Easings.CubicOut)
        .To(1))
    .Build();

var player = box.Play(timeline);
```

## Why evaluation is a pure function of time

`IAnimationNode.Evaluate(t)` computes the state at `t` from the keyframes alone. It never looks at the previous frame, and it never accumulates. Write code that leans on this rather than working around it:

| You want to… | Do this | Not this |
|---|---|---|
| Scrub from a `Slider` or gesture | `player.SeekProgress(x)`, or bind `KeyframeView.Progress` two-way | Rebuild a timeline at the new position |
| Reverse mid-flight | `player.Rate = -1` (or a negative `Speed`) | Build a second, reversed timeline |
| Export frames | Sample at exact frame times — identical bytes every run | Render off a real-time clock and hope |
| Test timing | Step a `ManualClock` | `Task.Delay` and a tolerance |

## Limits worth knowing up front

- **Everything ticks in managed code on the UI thread.** Transform and opacity tracks map 1:1 onto `CAKeyframeAnimation` / `ObjectAnimator` / `ScalarKeyFrameAnimation`, so native compositor offload is the design's biggest remaining performance win — but it isn't implemented yet.
- **Layout-affecting properties cost a measure/arrange every frame.** `WidthRequest`, `HeightRequest`, `Margin`, and `Padding` all work and are flagged by `AnimatableProperty.InvalidatesLayout`, but prefer transform and opacity where you have the choice.
- **There is no Lottie parser.** `KeyframeScene` is the scene graph one would need, but nothing reads a Lottie JSON file today.
- **MP4/video export is out of scope** — that needs a real codec. Pipe `FrameExporter.Frames()` to ffmpeg's stdin instead. APNG and WebP aren't implemented either.
