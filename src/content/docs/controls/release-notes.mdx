## 1.0 - TBD
* Added (MAUI): **video recording quality is now controllable** on `CameraView` — `VideoQuality` (`Lowest`/`Low`/`Medium`/`High`/`UltraHigh`/`Highest`), plus optional `VideoBitrate` and `VideoFrameRate` hints. Previously every platform hardcoded its own: CameraX recorded at 720p, AVFoundation at `PresetHigh`, Windows at 720p — so the same app produced visibly different footage depending on where it ran. **Behavior change:** the default is now `High` (1080p) everywhere, which raises Android and Windows from 720p and makes Apple deterministic rather than device-dependent. Set `VideoQuality="Medium"` to keep the old Android/Windows resolution. These are session settings (both AVFoundation and CameraX fix the capture resolution when the session is configured), so they belong on the control rather than on `VideoRecordingOptions`, and a change is ignored mid-recording — it lands on the next one. Unsupported rungs fall back to the nearest supported resolution instead of failing to start the camera.
* Fixed (iOS / Mac Catalyst / macOS): recording **with** a burn-in overlay produced a different encode than recording without one. The overlay path owns its own `AVAssetWriter` and was passing only codec and dimensions, so AVFoundation picked its own bitrate — meaning toggling `VideoRecordingOptions.Overlay` silently changed the size and fidelity of the output. It now honours `CameraView.VideoBitrate` like the native path.
* Sample: the DataGrid demo trimmed to three columns with explicit star/absolute widths. `Width="Auto"` cannot align on MAUI — the header, footer and every row are separate `Grid`s, so an `Auto` column sizes to its own cell's content and the columns drift apart. Prefer star or absolute widths.
* Sample: fixed the BadgeView corner-position demo — the `BadgeView` was stretching to fill its grid cell while the button inside was centred, so badges anchored to the cell corners instead of the button.
* Sample: the MediaPickerButton demo gained **Load Sample Photos** / **Clear** buttons so the populated state can be seen without granting photo-library access.
* Docs: added a [FrostedGlassView](/controls/frostedglass/) page covering both hosts, the per-platform blur implementations, and the Android 11-and-below tint-only fallback.
* Docs: removed the AI Prompt page — the control was never shipped.
* Fixed (MAUI): `IDialogService` dialogs stopped appearing after navigating away from the first page that showed one. The dialog overlay was created once per `Window` and permanently attached to whichever page was current at that moment, so every later call rendered into an off-screen page — nothing was displayed **and the awaited `Task` never completed**, leaving the calling command stuck in-flight. The overlay is now resolved against the current leaf page on every call, matching the documented "auto-attaches to the current page" behavior.
* Fixed (MAUI): `TextEntry` could not be typed into on Android. Tapping the control focused the entry and then immediately lost focus, so the keyboard never stayed up. The focus glow was applied by assigning a new `Shadow` to the control's border on every focus change, and re-applying a shadow on Android clears focus from the input inside it. The glow is now a single `Shadow` created with the control whose brush/opacity are toggled instead.
* Initial release of the controls packages for MAUI and Blazor.
